# E04 — selected-regime chamber interactions

Registered before interaction test execution. Depends on the three-engine E03 checkpoint and recorded codex-selected-winner (Pixi.js); implementation preparation may proceed before checkpoint closeout. Matt reserves VFX comparison in other regimes. Original suite evidence is unchanged.

H05/H06/H07: one shared layout/state model drives navigation, swept collision, painted object state, sorting and deterministic reward events. E03 floor, pillar and mage candidates are reused unchanged with explicit runtime masks. New object candidates use opaque sources plus independently annotated runtime silhouettes, because the native-alpha generation branch failed twice. Masking does not qualify animation or fine translucency.

State contracts: door locked→closed on unlock; closed→opening→open after 0.5s; open→closing→closed after 0.5s, reject closing when any actor occupies expanded door footprint. Closed/opening/closing block passage; open clears only the door owner. Crate intact→broken clears its own blocker. Chest closed→open→looted emits exactly one stable reward ID, with pickup exactly once. Save/reload round-trip preserves events and object state. Exit/re-entry does not reset rewards. Door is a sliding barrier; its runtime visual displacement is coupled to the same event clock. Animation is mechanical object motion, not character walking.

Movement: logical metres, 0.1m navigation grid, conservative square clearance using radii 0.35m/0.65m. Eight neighbors, continuous segment-vs-expanded-rectangle sweep and explicit corner checks; navigation and movement collision are separate consumers. Boundary exits use inward approach positions by radius+0.05m. Zero forbidden paths, wall penetration, corner cutting, stale blocker removals, duplicate rewards or lost state. Projection inverse round trip ≤0.5px equivalent; event/render state delay ≤one 60Hz tick under deterministic replay. No target frame-time PASS without a user-approved budget.

Tests include both perimeter directions, reachable object approaches and both exits in permitted door states, locked/closed rejection, unlock/open/traverse/occupied-close/replan, crate route changes, chest duplicate/reload events and front/behind ordering. Bad controls inject corner-cut segments, stale open-door blocking, overlapping-owner removal and duplicate reward events. Controls must be rejected. Diagnostic stand-ins remain explicitly labelled and cannot pass painted-monster/NPC/prop quality.

Limits: ≤5 built-in imagegen calls for separate door/crate/chest/monster/NPC asset candidates, zero paid API/service calls, ≤90min active work, ≤250MB artifacts, ≤5 capture batches (≤5min each); stop a branch after two identical failures. No silhouette extraction by colour thresholds or Python art editing. Runtime masking/texture transforms are the tested representation. Capture normal-speed playback plus separate debug views and raw event/assertion records. Performance telemetry is observed, not compared to an invented target. Gear and VFX remain separately registered experiments after this checkpoint.

This is a 2D textured-mesh presentation of explicit height data, not a production 3D rig or a change to C. The purpose is to make structural footprints and gate movement agree with geometry instead of inheriting a generated prop's uncalibrated view. Original painting bytes stay unchanged.
