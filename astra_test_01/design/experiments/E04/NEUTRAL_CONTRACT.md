# Portability constraints — Matt directive, 2026-09-11

**Godot is the shipping target; Pixi is the test harness.** Pixi's checkpoint selection authorizes a test workflow, not a change of shipping engine. The Godot runtime/importer is future work against this specification; it is not already implemented by this structure.

1. Every character/animation/VFX has an engine-neutral JSON asset manifest: immutable source path/hash, frame list, fps or null for a still, anchor/pivot, direction and qualification status, hitbox, emissive-mask path or explicit null, atlas coordinates, and declared effects. Runtime mask polygons are data. No Pixi/Godot/Phaser classes or filter instances in the schema.
2. `sim/index.mjs` is the pure JSON boundary: `{content,state,commands,dt_ms}` in; `{state,blockers,outcomes,visual_events}` out. Headless Node tests execute it. `sim/chamber.mjs` owns navigation, swept collision, clock, door/crate/chest transitions and rewards. Movement speed/path advancement also live behind this boundary. There are no rendering, DOM, camera or asset imports in sim. Actual combat-pipeline integration remains unimplemented; this is explicitly a chamber fixture, never mislabelled pipeline content.
3. `pixi-adapter/` is the replaceable view folder. Camera/inverse projection, texture import, masks, meshes, visual interpolation and rendering live there. UI converts input to commands and displays returned state. Authoritative-event buttons are test controls; they are not a finished proximity-gated interaction UI. Fixture placement is explicitly test-mode-only. The renderer may interpolate a gate's visual opening from returned time/state; it does not decide when the gate becomes passable.
4. Per-entity effects are JSON declarations: `{"kind":"flash","color":"#e4c46f","ms":150}` and the same typed shape for tint/glow/outline. The sim carries descriptors and their lifetime; the adapter implements only effect kinds actually exercised. Unsupported kinds must be reported, not silently approximated or counted as qualified. No engine filter chains are serialized. VFX textures, phases and event timing will extend the same manifest contract in their bounded experiment.

No new rendering/Steam/packaging claim follows. A Godot importer will consume the manifest rather than reverse-engineer this Pixi code. The current four constraints govern every subsequent asset and test prompt; older immutable prompts remain historical evidence.
