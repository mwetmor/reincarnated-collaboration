## Positioning Algorithm Tradeoffs (Criterion 7 / Dispatch § 1.4)

**Baseline — fixed-anchor + radial-projection (sunflower spiral):**

Properties observed:
- Deterministic: identical layout across reloads; useful for baseline-comparison communication
- Deliberate buffer by construction: anchors placed at fixed grid positions; buffer is the space outside all zone radii
- Primary-zone min NN: 40.7px (driven by physical element; 428/1000 kits are physical-primary — corpus imbalance, not algorithm failure)
- Dynamic zone radius: `outer_r = sqrt(n × kit_r² / 0.35 + inner_r²)`, capped at 1200px. Keeps packing density ~35% regardless of corpus imbalance
- Buffer-zone kits (310 hybrids) cluster at inter-anchor midpoints; buffer-zone min NN: 29.7px (expected — hybrids share midpoint destinations)
- Performance: pre-computed (0.13MB JSON); zero runtime compute

When to prefer: when buffer must be guaranteed by construction; when corpus imbalance would distort force-directed results; when determinism matters for communication.

**Alternative — force-directed (anchor-spring + inter-kit repulsion):**

Properties observed:
- Min NN: 94.5px (vs 29.7px baseline) — substantially better kit separation
- Buffer emerges from physics: anchor springs pull kits toward anchors; inter-kit repulsion creates natural clearance between clusters
- Hybrid kits (stronger spring K×1.8 toward midpoint) land in buffer organically without explicit placement
- 80 iterations × 1000 kits with BUCKET=450px spatial bucketing: ~3 seconds precompute offline; 0.15MB output
- Organically handles corpus imbalance: physical cluster expands under repulsion rather than packing into fixed annular zone
- Non-deterministic across different initial conditions if seeds differ (current implementation: positions seeded from baseline, so identical runs are deterministic given same baseline input)
- Buffer definition is emergent, not geometric: the "deliberate buffer" criterion (criterion 3) is satisfied by force equilibrium, but the buffer width is not guaranteed to match design intent across different corpus sizes

When to prefer: when kit separation quality matters most; when corpus size may change significantly (force adapts; spiral zone radius needs tuning); when organic spatial arrangement reads more naturally than designed grid.

**Summary tradeoff:** baseline guarantees buffer by construction and handles corpus imbalance explicitly via dynamic zone radius; force-directed produces better kit separation and more organic spatial coherence. For player-facing production: force-directed visual quality, with baseline as design-validation tool. Neither method is clearly wrong. Post-Phase-3 elrond methodology consultation per Discipline #18.2 should address whether force-directed or a UMAP-based approach better preserves substrate-vector proximity (criterion 2) — which Phase 3 cannot rigorously verify without substrate-vector distance metrics.

## Buffer-Space Content Design Observations

**What landed:**
- 310 hybrid kits at inter-anchor midpoints, weighted by PSS contribution of each element pair
- Dual overlapping circle render (two-element color blend) distinguishes buffer-zone kits from primary-zone kits in dot mode
- Buffer-only lasso reliably surfaces hybrid kit content when drawn in inter-anchor space

**Observation 1 (YELLOW — corpus gap):**
PROVISIONAL corpus contains no rare-lineage kits. Criterion 4 accepted with hybrid kits as buffer content stand-in. The "rare-lineage discovery moment" (dispatch § 4.5 quality criterion) cannot be validated until the engine generates rare-lineage kits per 2026-05-23 marginal-lineage recognition records. Criterion 4 passes on technical grounds; fails on narrative fidelity grounds. Flag for next corpus expansion.

**Observation 2 (YELLOW — physical element dominance):**
Physical element comprises 428/1000 kits (43% of corpus; expected per PROVISIONAL corpus architecture). This creates visible over-representation at the physical anchor: the physical nebula cluster is substantially larger than other element clusters. At 2× zoom, the physical star field is visually denser than other anchors. Two possible interpretations: (a) this is substrate-accurate (physical primary is genuinely over-represented in current corpus) or (b) this reads as a physical element bias that may confuse players. Recommend Matt call on whether physical dominance should be preserved (faithful corpus rendering) or normalized (visual balance across anchors). Flag for Pattern B with Matt post-Phase-3.

**Mid-buffer feel:** buffer zones feel appropriately sparse at 1× zoom (anchor nebulas readable as distinct islands). At 2×+ zoom the buffer is mostly dark space with scattered hybrid-kit stars — which IS the discovery feel the dispatch targets. The 11000×8500px world size gives adequate inter-anchor clearance.

## Lasso Ergonomics Observations

**What works well:**
- Within-anchor mode fires reliably when lasso is tight within visible nebula cloud
- Cross-buffer mode fires when lasso extends across inter-anchor gap; badge reads clearly
- Buffer-only mode fires when lasso placed in empty buffer space; surfaces hybrid kits

**Touch ergonomics:**
- Pinch-zoom + lasso separation works: two-finger pinch triggers pinch handler exclusively; single-finger drag triggers lasso (in lasso mode) or pan (in pan mode). No gesture interference observed.
- At 375px viewport (mobile), lasso drawing is ergonomically tight — small world region visible at 1× zoom. Recommend: consider defaulting to 1.5× zoom on first load for mobile so more of the canvas is visible and lasso targets are clearer. This is cosmetic; not a criterion-3.4 block.

**Lasso classification threshold (Observation 3 — YELLOW):**
`classifyLasso()` uses three hardcoded scaffold thresholds (not `anchor.outer_glow_radius`): `within_anchor_centroid_threshold=1100` (centroid distance < 1100 → within-anchor), `nearby_anchor_threshold=1200` (distance < 1200 + lassoR counts an anchor as "nearby"), `cross_buffer_min_lasso_radius=600` (lassoR > 600 required to trigger cross-buffer when two or more anchors are nearby), and `min_lasso_polygon_points=2` (degeneracy guard). These are scaffold values (#40 candidates per dispatch § 4.5 refutation conditions). They were calibrated for 8 anchors at the current world size (11000×8500px, SPACING_X=2750px). They do not read from `anchor.outer_glow_radius` or any per-anchor property — they are fixed numeric constants in the function body. If anchor count or world size changes materially (e.g., adding zodiac anchors post-Legolas commission), all four thresholds should be re-validated against the new geometry. ## Methodology Hotspots (Discipline #18.2 — fire post-baseline)

Two hotspots are now concrete from Phase 3 findings:

**Hotspot A — Substrate-vector proximity (criterion 2) unvalidated:**
Phase 3 places kits near their primary element anchor by construction (radial baseline) or by anchor-spring (force-directed). Neither method uses actual substrate-vector distance metrics to validate that spatial proximity reflects substrate similarity. Criterion 2 passes on face (element neighborhoods visible) but the substrate-similarity claim is not rigorously validated. Elrond methodology consultation should define a substrate-vector proximity metric and evaluate whether current layouts satisfy it. Trigger: post-Phase-3 elrond consultation per Discipline #18.2.

**Hotspot B — Algorithm selection (force-directed vs UMAP):**
Phase 3 compared radial vs force-directed. The dispatch § 1.4 table also lists UMAP (non-linear; preserves local structure; loses axis interpretability) and Voronoi (territory partitioning; clean boundaries; loses gradient). Phase 3 cannot distinguish between these approaches empirically without substrate-vector distances. After elrond defines the substrate-vector metric (Hotspot A), a UMAP comparison at the substrate-vector level would be the next empirical step.

## Subset-Bias Observation (Dispatch § 8)

Phase 3 used 8 element-family anchors (fire / water / earth / wind / lightning / holy / shadow / physical) — the canonical-7+1 framing from atomic-substrate-registry.

Did the anchor framing materially shift architectural-pattern findings?

No major shift observed. The two-layer + buffer-space pattern works at 8 anchors and would generalize to more or fewer. The main constraint is visual: at 8 anchors on a 4×2 grid with 11000×8500px world, inter-anchor buffer (~2230px minimum gap) is comfortable. At 12 anchors the grid would need expansion or a different topology (e.g., 3×4 or circular arrangement) to preserve buffer distinctness.

Zodiac anchors (post-Legolas commission) represent a different framing: ~12 zodiac signs as anchors vs 8 elements. This would stress-test the buffer-space architecture at 12-anchor scale. Phase 3 findings suggest the architecture scales cleanly — the buffer emerges from anchor spacing, not from anchor count, as long as world size is adjusted proportionally.

Weapon-form-family anchor framing (5-7 clusters: blade / ranged / magical / brawl / hybrid) was not tested. The element framing was clearly the right prototype choice: element is the existing canonical substrate dimension, making visual verification of criterion 2 (spatial proximity = substrate relationship) tractable without additional analysis. Weapon-form framing deferred to Pattern B with Matt post-Phase-3 if needed.
