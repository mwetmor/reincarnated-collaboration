## §6 — F-SA-1. THE BIGGEST THING THIS CELL FOUND, AND IT WAS NOT IN ITS SCOPE

**Every COMBAT-JUICE particle system in `wr2_playback.gd` has been running on a random per-process
seed, and it is why four cells of pixel gates have been fighting a noise floor.**

`vfxbo_arms.gd::_fix_particles` has always set `use_fixed_seed = true` and a deterministic seed on the
bake-off arms. COMBAT-JUICE-1 shipped its **own** loader and its **own** `_cj_fire`, and `_cj_fire`
only ever called `restart(); emitting = true`. So the whole cell-3 layer — `BloodCurse`,
`ShieldAuraBlue`, `MuzzleFireballRed`, `ChargeSphereRed`, `SurfacePoolSplat`, `DeathNormal`, the gore —
re-randomised on every process. **209 emitters on this fight.**

**The evidence was already banked before I found the cause**, in TELL-DRESS-2's own three passes:

| pass | peel set | baseline @ frame 5 |
|---|---|---|
| 1 | `--tgbody 0 --nomark 1` | 2,431 px |
| 2 | + `--nodust 1 --nonum 1 --noambient 1` | 379 px |
| 3 | + **`--cjuice 0`** | **0 px** |

Cell 2c named the residue *"the ambient dust layer, seeded per process"* (F-TD2-1) on the strength of
pass 2. **Pass 3 is what actually zeroed it, and pass 3 is the one that peels this.** ⚑ **F-TD2-1's
largest term was never the dust.** I wrote that finding four hours ago and this cell falsified my own
attribution — the peel set was right and the name on it was wrong.

**Fixed at one place.** `_cj_load` now walks every instantiated effect and sets
`use_fixed_seed = true` with a deterministic key; `restart()` on a fixed-seed emitter replays the same
realisation. The counter is deterministic because the spawn ORDER is trace-driven and identical across
