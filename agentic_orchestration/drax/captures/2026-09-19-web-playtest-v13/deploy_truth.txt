== THE ONE ERROR — upstream, pre-existing, reproduced faithfully, NOT mine to patch ==
══════════════════════════════════════════════════════════════════════════════════════
Arm B logs exactly three console errors in the local run — one per cast, none on arm A:

  ERROR: Cannot open file 'res://vfx/blackwater_cocktail_e3_V/materials/Additive.tres'.
     at: load (scene/resources/resource_format_text.cpp:1430)
     GDScript backtrace: [0] _cast_frame_changed (res://scripts/keeper.gd:276)
  ERROR: Failed loading resource: res://vfx/blackwater_cocktail_e3_V/materials/Additive.tres.

CAUSE, located in the pack and not inferred. keeper.gd:276 is the cast_kit_index == 18
branch and it hardcodes a load of the V kit's materials/Additive.tres for the muzzle
FLARE. Every other e3 kit emits that file. The V kit does not — its materials/ holds
only Body.tres, Field.tres, ending_smoke.gdshader and
vfx_material_mix_unlit_order_fbc0ebc0c789_outside_in.gdshader. Verified in the SOURCE
pack, so the file is absent upstream; it is not something the mirror dropped.

IT IS IN THE ARTIFACT OF RECORD. runs/C-7/t3/AB-v45/events_B_E.log carries the identical
pair of lines at the identical keeper.gd:276, and events_A_E.log carries none. So the
defect predates this build, gandalf's accepted A/B proof was rendered with it present,
and my pck reproduces the pack exactly. This deploy neither introduces it nor hides it.

BLAST RADIUS is small and bounded: load() returns null, flare.material is left null, and
the cast flare at the staff draws with the default material instead of the additive one.
The flipbook FIELD BODY is unaffected — it uses Body.tres / Field.tres, which exist and
load. That is consistent with the field body rendering correctly in both my local frames
and gandalf's sheets.

RAISED, NOT PATCHED. I do not author pack content and I do not write under
astra_test_01/burst/. Routing this to gandalf as a C-7 finding. It is the same SHAPE as
F-C7-1 (the V kit's config referencing an unemitted derived/field.png, dispatch only in
the picker) — a second instance of "the V kit names an asset the emitter does not emit",
which suggests the class is worth a sweep rather than another one-off fix.

  ⚑ AND IT IS A FENCE GAP WORTH NAMING. The build's dangling-res:// fence passed, and it
  was right to pass: it only walks .gdshader paths, because shaders were what bit web11.
  A missing .tres is the same failure with a different extension and the fence is blind
  to it. Widening it is not free — .tres paths in a pck include remapped and generated
  ones, so a naive widening would fire false positives, which is the exact defect web12
  had to correct in the license fence. Noted here as a known gap with a named cost
  rather than widened in haste during a held deploy. The cheap interim check that DID
  catch it is the one that caught it: run the kit and read the console.
