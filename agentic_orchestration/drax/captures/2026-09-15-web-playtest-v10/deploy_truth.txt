== THE CHECK THAT MATTERS: production touch-emulated cast ==
VERDICT: FORWARD. On production, under real touch emulation, on both axes.

Harness: touch_cast_test.js (beside this file). Playwright chromium, phone-landscape
844x390 CSS px at dsf 2, hasTouch: true + isMobile: true, and every touch delivered as
a genuine CDP Input.dispatchTouchEvent. THE MOUSE IS NEVER MOVED at any point in the
run — so if aim were still reading the pointer, it would read whatever the browser's
compatibility layer last reported, which is the failure web9 caught.

The build agrees it is a touch device (live_touchflags.json):
    maxTouchPoints 1, 'ontouchstart' in window true, window.TouchEvent function
That is what DisplayServer.is_touchscreen_available() reads on web, so the new branch
in keeper.gd is the LIVE branch in this run, not the desktop fallback.

Method — and one deliberate addition to the dispatch. East alone is a weak test here:
the CAST button sits bottom-RIGHT, so "forward when facing east" and "at the CAST
button" both land to the right of the Keeper and the frames would not separate them.

forward aim lands LEFT and an emulated-mouse aim lands RIGHT. Both were run in one
session on the live URL, kit fire_burst_e0p_v2 (Tab x7), joystick drag to set facing,
release, then tap CAST at (700, 314).

== harness notes for the next deploy ==
Touch: hasTouch + isMobile on the CONTEXT is not enough on its own to prove which
  branch ran — read navigator.maxTouchPoints / 'ontouchstart' from inside the page and
  file it, because that is the value DisplayServer.is_touchscreen_available() derives
  from. touch_cast_test.js writes it to <label>_touchflags.json every run.
Direction: always cast in a direction that points AWAY from the on-screen control you
  suspect. A single east-facing cast cannot distinguish "forward" from "at the CAST
  button" in this layout, and would have passed either way.
Kit choice: for any aim question in headless, use a slow kit (frozen_orb). At
  swiftshader screenshot cadence (~0.8 s/frame) a fast burst detonates between frames
  and you photograph the cast pose instead of the landing.
