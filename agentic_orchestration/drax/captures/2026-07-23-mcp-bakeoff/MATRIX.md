## IvanMurzak P1 retry (annex) — outcome

**Question:** was IvanMurzak's isolated blank a Metal/Forward+ hardware limit, or a fixable capture-path bug? **Answer: a render-frame-settle bug.** Full write-up + evidence in `ivanmurzak-p1-retry/RETRY_FINDING.md`. The exact graded addon build (4.1.0) was working-tree-only on the deleted branch and is unrecoverable (HEAD is drifted 0.19.1), so re-standing that version faithfully was impossible. Instead the retry's root-cause question — addon-agnostic — was answered directly on the live Godot 4.6.3 STANDARD editor via `execute_editor_script`: a self-built isolated `SubViewport` (own World3D, UPDATE_ALWAYS, BoxMesh + light + camera) read **synchronously** (`force_draw` ×6, no await) → **BLANK** (0 non-bg px); read after **frame-settle** (`await RenderingServer.frame_post_draw` + `await get_tree().process_frame` ×2) → **renders the lit cube** (verified by eye). Same host, same viewport — the only variable is awaiting post-draw. **Conclusion:** isolated World3D SubViewport capture is VIABLE on this Metal host; IvanMurzak's 1892-byte captures came from reading the texture before the GPU settled. Its P1 grade is therefore "blocked by a fixable tool bug," not "blocked by the host."
