## Scope

### Item 1 — Remove H/M letters under potion icons

In `potionHud.ts` (and `mobile/touchPotions.ts` if it duplicates the labels):
- Remove the "H" / "M" / "HP" / "MP" text glyphs rendered below each potion icon
- Keep the count badge (e.g., "×3")
- Player learns blue = mana, red = health from color alone (genre convention; redundant labels = visual noise)

If a label is needed for accessibility/screen-reader purposes, retain as DOM-level alt-text only (not visible glyph).

### Item 2 — Dash cooldown HUD indicator ("running man")

Add a new HUD icon to the left of (or in line with) the potion HUD:
- **Icon:** simple running-figure silhouette OR procedural arrow-burst glyph (your call; match the existing potion icon visual register)
- **Layout:** position-adjacent to potions in the bottom-left cluster; size match potions
- **State rendering:** mirror skill-icon cooldown pattern:
  - Ready: full opacity / saturated color
  - Cooling: dimmed + radial sweep (or simple fill-up bar) showing `_dodge.cooldown / DODGE_COOLDOWN` progress
  - Just-fired (0-0.2s): brief flash to confirm input was accepted
- **Source of truth:** `_dodge.cooldown` (already exists in main.ts at line 1248 / 1289)

Consult drax v0.32's PotionHud x=132 / DesktopHudIcons (14,14) layout to find clean room for the new icon. If layout constrained, place icon LEFT of potion cluster (so it reads "dash, then potions" left-to-right in the player's eye-line).

### Item 3 — Dash range extension

Current: `DODGE_DISTANCE = 120` px.
Target: **210 px** (1.75× — midpoint of Matt's 1.5-2× ask).

Rationale for 1.75×:
- 1.5× (180 px) feels conservative for an "evasive maneuver"
- 2.0× (240 px) risks teleport-feel and over-traversing AOE telegraph windows
- 1.75× lands between the two; tune-during-impl latitude granted

If 1.75× feels too long during your build smoke (e.g., dashes through walls more often, dashes past intended escape distance), drop to 1.6×. If too short, push to 1.85×. Document chosen final value in completion record + STATE entry.

`DODGE_DURATION` should remain `0.18s` (ease-out) — same duration, longer reach = faster apparent dash speed, which matches the "evasive" intent.

**Out-of-scope reminder:** do NOT add a separate "dash speed" param. Distance + duration is the contract.
