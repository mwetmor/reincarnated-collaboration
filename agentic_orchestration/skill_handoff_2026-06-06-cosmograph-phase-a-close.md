### Interaction-architecture arc

Three Pixi v7 event-routing nuances surfaced + resolved during post-Gate-2 polish:

1. **Phase 5b lasso coord-transform** — `FederatedPointerEvent.globalX/Y` is CSS-pixel pre-stage-transform; Phase 5's zoom + pan created non-identity stage transform; lasso polygon drifted by stage transform delta. Fix: `toStageLocal(globalX, globalY, stage)` inverse-transform helper. Same fix applied to faction-click hit-test. MIN_DRAG_PX intentionally kept in screen-space (substrate-led judgment: screen-pixel threshold shouldn't scale with zoom)
2. **Phase 5c pan event-routing** — root cause NOT delta-math (as initial hypotheses ranked) — Pixi v7 dispatches pointermove via hit-test against stage's `hitArea = Rectangle(0,0,w,h)` in stage-LOCAL coords; after pan, hitArea's screen-space coverage shifts with stage origin; mid-drag cursor enters region where stage-local position falls outside hitArea → hit-test fails → pointermove stops being delivered → "pushes off the entire screen" symptom. Fix: migrated pan + faction-click to native DOM events on container + document (mirrors wheel-zoom pattern already in use); LassoLayer federated events preserved
3. **Mode-toggle UX pattern selection** — Option A (toolbar) chosen over Option B (modifier-key) for discoverability; default Pointer mode (pan + grab cursor) + opt-in Lasso mode (crosshair cursor); zoom + faction-click preserved in both modes
