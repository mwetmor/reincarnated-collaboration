## 2. Pre-commit vs escalate — decision heuristic

**PRE-COMMIT (LOCK A-J authority):**
- Is it ADDITIVE? (new fields / new prompt references / new consumer-format)
- Does it preserve EXISTING SEMANTIC behavior of canon?
- Is it REVERSIBLE without amendment-pass discipline (i.e., can consumers ignore the addition without breaking)?
- **If all 3 YES → pre-commit**

**ESCALATE (escape clause):**
- Does it CHANGE existing canon semantically?
- Does it touch CANONICAL-7+1 catalog or BC axes or Q18 lock?
- Does it require AMENDMENT-PASS discipline to revert?
- Does it affect `foundation/elements.py` or `canonical/library_schema`?
- **If ANY YES → escalate**

**When in doubt:** jack-ryan critique-pair Gate-1 pre-fire arbitrates (jack-ryan direct-approval authority per ADR-002 for documentation + process scope; architectural arbitration escalates if jack-ryan cannot ratify).

KR escalates to Matt ONLY for:

1. **canonical-7+1 catalog amendments** — `config/elements.yaml` field changes to rotating primaries, ailment definitions, resistance types, color ranges, scales_with

3. **Q18 vocabulary lock amendments** — pool.json entries IMMUTABLE in immediate-arc; new entries beyond Q18 lock require Matt architectural authority
4. **Substrate composition policy SEMANTIC amendments** — Option α / β / C semantic shifts (e.g., reframing martial 5-tuple definition); additive consumer-side adjustments pre-commit per LOCK J § 3 but SEMANTIC shifts still escalate
5. **`foundation/elements.py` amendments** — engine foundation layer touches
6. **`canonical/library_schema` amendments** — engine internal canonical library structural changes
7. **ADR-tier amendments** — any ADR-002 architectural-commitment-tier scope per AGENTS.md governance
8. **Cross-seam contract SEMANTIC changes** — gamora simulation fight-engine contract changes vs additive output-format extensions (additive pre-commit per LOCK J § 4; semantic changes escalate)
9. **Strategic direction OUTSIDE IA chain scope** — long-arc reactivation, pivot direction, scope expansion beyond IA-1/IA-2/IA-3

**KR does NOT escalate for:** routine workstream execution, substrate-curation within pre-committed scope, documentation amendments, operational choices, or design-quality observations within audit discipline.
