The D-floor draw pool `_MOBILITY_GEOMETRIES ∩ PHYSICAL_GEOMETRY_PALETTE = {defensive_dash, leap_strike, dash_attack}` is correct, entirely within the physical palette, and disjoint from `CASTER_ENVELOPE_GEOMETRIES`. **No floor skill can land on a caster geometry under any code path. A1 is refutation-proof.**

A2 (smuggle-test) passes as written: each rule keys on a single coordinate (`def_bin`, `eng_bin`, `geo_bin`, `geo_bin`), and each fires on a non-rogue cell (warrior/hunter/mage-fire for D via `damage→glass`; warrior/skirmisher for M via `-fast`; warrior/grappler for A and B via `close→single-target`). The burst reconciliation is coherent: retaining `power_tier>=60` (`:248`) as a probabilistic up-weight on the free-draw path does NOT reintroduce the "no burst below 60" hole, because the hole was the *absence of any floor* — the B floor is now an independent reservation orthogonal to the power gate.

**What the math-note glosses (the amendments):** A3's distinctness proof rests on an orthogonality claim that is true only under a draw discipline the note asserts but does not pin, and two of its sub-pool cardinalities are stated too generously for the melee case.

## Rationale

**A3's "7 distinct AoE available" is wrong for a melee cell, and the real margin is zero-slack (Discipline #1.2 — code-cited math must be exact).** Math-note §4 line 263 claims the A-floor (4 slots) draws from "7 distinct" AoE geometries. But `_AOE_PHYSICAL_GEOMETRIES` (`weapon_envelope_composer.py:103-105`) contains 7 only because it includes `multi_projectile`, `fork`, `ring` — which are `RANGED_PHYSICAL_UNLOCK` (`:66-70`), NOT in the melee `PHYSICAL_GEOMETRY_PALETTE` (`:49-61`). For the rogue cell (melee), `_AOE_PHYSICAL_GEOMETRIES ∩ melee_palette = {cone, ground_slam, melee_arc, whirlwind} = exactly 4`. So 4 distinct AoE-role slots draw from a pool of exactly 4: satisfiable, but with **zero slack**. Likewise the M-floor (2 slots), after D consumes `defensive_dash`, draws from `{dash_attack, leap_strike}` = exactly 2: also zero-slack. I verified the aggregate: the union of all four floor sub-pools (melee-restricted, D-before-M deconflicted) is exactly all 11 melee geometries, and the 8 reserved slots tile 8 distinct melee geometries IFF each is drawn distinct-first within its sub-pool. Under that discipline, 3 melee geometries remain for the 5 free slots → `geometry_only_distinct = 11 ≥ 10` holds. But the §4 orthogonality claim ("the floor REASSIGNS which role each drawn geometry carries; it does not shrink the geometry pool") is only true if the floor reservation is itself a distinct-first draw within its sub-pool. If the implementation reserves the A floor as "4 AoE-role skills, any AoE geometry (with reuse)," it can collapse to 1 distinct AoE geometry and the 11-distinct proof fails. The note's §4 asserts distinct-first behavior for the free draws (`_draw_geometry_distinct_first:217-226`) but does not state that the *reserved floor slots* must also be distinct-first-within-sub-pool. That is the knife-edge the implementation must honor.

**The §2 D-before-M ordering note (lines 206-208) is correct but under-stated.** It correctly says reserve D first then M from remaining mobility geometries so the 8 slots are 8 distinct skills — but it frames this as a double-count guard, not as the (binding) condition for the zero-slack distinctness margin. Same mechanism, higher stakes than the note conveys.

These are WARN-level (math softness), not BLOCK — the math is sound and the kit is buildable; the note simply states two pool sizes optimistically and leaves the load-bearing draw discipline implicit.
