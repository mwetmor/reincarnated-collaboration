## F1 — geometry field-name reconciliation

### What I found
gamora's two charter-staleness catches are SUBSTANTIATED against disk: `_lever_geometry_mix` does not exist in the live tree (it died with the deleted 1D balance-loop; only a locked stale worktree matches), and `damage_geometry` is a BC-axis signature label (cohort descriptor), not a per-skill hit-geometry field — neither is the locus. The real defect is exact and narrow: a live `Skill.model_dump()` carries the rich 24-type geometry under model field `geometry` (`skill_schema.py:17`), but `_determine_geometry_type_with_source` read only `spatial_geometry_type` (Path 1) and `geometry_type` (Path 2, the export-renamed name), so the in-harness path fell to the Path-3 name-keyword heuristic = geometry-blind. The fix widens Path 2 to read the rich value under EITHER key through the SAME `_RICH_TO_SPATIAL` table. I independently confirmed the `.py` diff touches ONLY the docstring, the Path-2 fallback (`if rgt is None: rgt = skill_dict.get("geometry")`), and the Path-3 WARNING text — the translation table definition is NOT in the diff (UNCHANGED). I reproduced the smoke: **18/18 PASS**. The B-regression cases confirm Path-1 explicit still takes precedence and Path-2 still prefers `geometry_type` over `geometry` when both are present (genuinely behavior-preserving on every path except the broken one). The C-block end-to-end is spatially correct, not just different: a circle (AOE) kit hits **9/9** pack mobs vs the point (single-target) kit's **1** — the geometry distinction the heuristic was blind to.

### Rationale
Additive key-widening over an unchanged translation table is behavior-preserving by construction: a given rich value maps to the same spatial type regardless of the key it arrived under (Principle #1, math note §3 no-magnitude-change argument — verified). The ONLY dicts whose resolved geometry changes are those that were already falling to the heuristic guess (sgt absent AND `geometry_type` absent AND `geometry` present), where the change is heuristic-guess → correct rich-translation = strictly more faithful (#11). The fix is at the correct locus and the geometry-corrected outcomes MATCH the F1 §3 design map (`ground_targeted_circle → circle`) — charter §2.3 ENDORSE-the-BUILD criterion met (spatially correct).
