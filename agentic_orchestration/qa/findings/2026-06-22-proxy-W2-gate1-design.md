## Concerns — four carry-items to fold before pickup (none block the wave)

**CARRY-ITEM #1 (WARN — the spike's headline finding is not surfaced as a W2 acceptance boundary).** The de-risk spike's load-bearing finding (§5.1-5.4) is that the boss outcome is a near-deterministic **STEP, not a graded (0,1) band** — P1 was FALSIFIED as a stable band (graded only on a ~5%-wide knife-edge), and the grading actually lives on the **clear-TIME axis** (count wall → clear-time), not the WR axis. The W2 dispatch §Acceptance says "a fighting army kills the boss as a real graded build (the de-risk spike proved YES)." That phrasing slightly overstates the spike: the spike proved the army FIGHTS and KILLS gradedly-ENOUGH to be load-bearing on `boss_with_adds`, but it did NOT prove a stable graded WR band — that is the open W3 encounter-model question (death-channel vs efficacy/time-band grading), pre-cleared to gandalf per MASTER §DESIGN-PRE-CLEAR. **Recommend:** soften §Acceptance to "kills the boss as a real fighting contribution (the spike proved the army is load-bearing on `boss_with_adds`; the STABLE graded-band shape is W3's encounter-model calibration, not W2's claim)." This keeps W2's acceptance bar at "the fight WORKS" (mechanism) and does not let it back-door the W3 grading question the spike explicitly handed to gandalf+Matt. The fix is one sentence; the risk if unfixed is gamora over-scoping W2 to chase a graded WR band that the spike already showed is a knife-edge with the current no-death-risk model.

**CARRY-ITEM #2 (WARN — the `aggro_fraction` semantic-shift is the load-bearing W2 declaration, and it is under-specified in the dispatch).** Spec §8.1 and §2 name THE W2 semantic shift: `aggro_fraction` shifts from a lifetime-decay coefficient to a **spatial re-target SHARE** (the probability/share a mob re-targets onto a frontline proxy). The spike modelled tanking as the EXISTING `aggro_fraction × enemy_dps_est` attrition share and explicitly left the harder half — mobs SPATIALLY re-pathing onto the proxy — UNTESTED (spike §5.0 caveat, §5.5). The W2 dispatch §Disciplines cites #12 generically ("proxies go from positionless contribution-only to real fighting entities") but does NOT name the `aggro_fraction` reinterpretation as the specific shift W2 must declare in its math note + decisions-log. **Recommend:** add to §Disciplines #12: "declare the SPECIFIC `aggro_fraction` semantic shift (lifetime-decay coefficient → spatial re-target share, spec §8.1) — and state explicitly whether W2 implements the spatial mob-retarget (the spike's untested half) or keeps the attrition-share model and defers spatial-retarget to W3. Either is acceptable; the math note must DECLARE which, so the W2/W3 boundary on mob-aggro is crisp." This prevents the same nav/attack ambiguity W1 had — W2 should consciously state how far the mob→proxy aggro cross goes, exactly as W1 consciously declared the nav/attack decoupling.

**CARRY-ITEM #3 (INFO — name the death-path reuse site by content, as the dispatch did for the attack/COUNT sites).** §Scope bullet 3 ("Death — reuse the existing mob-death path; no special-cased proxy death") is correct but cites no anchor, whereas the attack-target and COUNT-gate bullets both give a find-by-content anchor. The existing mob-death pattern is `e.hp <= 0 → e.hp = 0.0; e.is_alive = False` (live at `:2245-2247`); the spike triggered proxy death off realized HP via the `_step_proxy_population` death logic (spec §4 cites the legacy `:1638` attrition-death). **Recommend:** add the content anchor "(reuse the `e.hp <= 0 → is_alive=False` pattern + the existing `_step_proxy_population` death/fission logic, now driven by realized damage instead of estimated attrition — spec §4/§5)" so gamora has the same find-by-content discipline on all three reuse sites, not two of three. Minor; tightens consistency.

**CARRY-ITEM #4 (INFO — seed base ceiling drifted; confirm the floor.)** §Disciplines #3 says "prior through 50,000,017; use 51M+." W1's actual base was `BASE_SEED = 50_000_017` (W1 dispatch said "50M+"; gamora used exactly 50,000,017, confirmed in my W1 Gate-2 §Gate-teeth-6). So 51M+ is correctly disjoint. **No change needed** — flagging only that the ceiling citation is now exact (W1 consumed 50,000,017) so 51M+ is clean; gamora should record the exact W2 base as W1 did.
