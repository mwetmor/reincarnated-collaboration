## § 3 · Findings

### WARN-1 · The function fingerprint cannot see a constant change or a re-homed code object (#75) → before E3

`_fdesc` fingerprints a function by (qualname, src-relative file, first line, sha256 of `co_code`). **`co_code` does not contain the constants, names or globals a function uses.** I demonstrated this at this Gate with a stdlib-only probe that imports the v3 script's own `_fdesc` (scratch, not evidence):

| Substitute | `_fdesc` equal to the original? | Behaviour equal? |
|---|---|---|
| the same source with literal `55.0` → `5.0` (a `PTH_MINIMUM`-style constant) | **True** | False |
| the **same code object** with **foreign `__globals__`** (`types.FunctionType(code, rulebook_globals)`) | **True** | False |

The second case matters more. Re-homing the sealed code onto rulebook operands is the **cheapest way to "transcribe term for term"**, so it is a technique a binder may genuinely use. In ORACLE at the GD profile, Limb A cannot see such a leak either, because the values are equal. The census is the only limb that can, and as written it cannot.

**Required before E3**, in the census and in the A-2 JSON that supersedes `CENSUS_FUNCS`:
1. **Extend the fingerprint:** sha over `co_consts` (recursively, with floats as bits), `co_names`, `co_varnames`, `__defaults__`/`__kwdefaults__` bits, closure cell contents (bits or repr), and `__module__`.
2. **Add an in-child boolean** `fn.__globals__ is sys.modules[<sealed module>].__dict__`. For methods, add `"<name>" in cls.__dict__` with that `__globals__` check.
3. **Add the § 2 (a) and (b) symbols.**
4. **Add two controls, predicted first:**
   - **nc8f:** re-home `threat.resolve_hit` onto a foreign globals dict with equal values → census RED on exactly `threat.resolve_hit`.
   - **nc8g:** a const-edited copy of one function at the same file and line → census RED.

### WARN-2 · The witness's child coverage is sound in mechanism, but not yet specified for the emitter's tree, and it reads modules only at exit → before E3

**What is sound** (checked against the emitter source):
- The emitter spawns each cell as `subprocess.run([sys.executable, HERE, "--cell", arm, salt], env=dict(os.environ, …))` (:882-895). The environment, `PYTHONPATH` included, is inherited, and each child re-runs `site`, so the witness loads in every cell.
- The cells are sequential, normal `python` processes with no `-S`/`-I`, fork or `os._exit`. So `atexit` runs, and on `SystemExit` too.
- A killed child leaves **no** record. That reads as coverage-short, which **fails safe**, provided the expectation is exact.
- nc8d proves a foreign `sitecustomize` displaces the witness and is caught.

**What is not yet right:**
- **(a) `witness_check` counts only DIRECT children of `root_pid`.** In the emitter's case the tree is launcher → emitter parent → N cells. With `root_pid` set to the launcher, `children_of_root` is 1, not 25, and `expect_children=25` would fail for the wrong reason. Set any other way, it silently checks the wrong level. The emitter parent itself must also be witnessed: it imports `kc2` for its LIMB 1-3 and installs every wrapper.
- **(b) N is not always 25.** `--inertness` runs `_run_cells` twice (hooked and `bare`, :968/:971), giving **50** cells.
- **(c) The module snapshot is taken at exit only.** A module that is imported, installs substitutions and removes itself from `sys.modules` leaves no trace in the record. The census runs only in the § 4.7 children, not in emitter cells.
- **(d) `sitecustomize` is a single slot.** In a JOIN interpreter the JOIN hook occupies it, so the witness cannot load there. JOIN-side per-pid evidence is A-1(3)'s job (the JOIN hook's own record), and should carry the same fields.

**Required before E3:**
- **(1) A tree expectation in `witness_check`:** exactly 1 emitter pid (ppid = launcher), plus exactly N cell pids with ppid = the emitter pid. N = |arms| × |salts| × (2 if `--inertness` else 1). The multiset of `(arm, salt, JOIN1_BARE)` comes from argv/env (add `JOIN1_BARE` and `JOIN1_CELL_OUT` to the record), with no duplicates, no extra pids, and no orphans.
- **(2) Import-event capture in the witness.** `sys.addaudithook` at `sitecustomize` time records every `import` event name, not only the exit snapshot. At exit, without importing anything, it also records the WARN-1 fingerprint for each A-2 / do-not-substitute symbol whose module is **already** in `sys.modules`. This keeps the witness stdlib-only and inert.
- **(3) The JOIN hook (E3) writes the same per-pid record shape**, so one checker reads both halves.
