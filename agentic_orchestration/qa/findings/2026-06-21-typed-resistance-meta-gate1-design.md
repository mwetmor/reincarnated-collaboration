### Claim-by-claim verification (all from live source)

1. **Substrate asymmetry (§2.A) — CONFIRMED.** Player offense is genuinely typed through `resolve_skill`: physical → `compute_physical_damage(magnitude, scaling_stat, defender.armor)` (`damage_resolver.py:460`); elemental → `res = defender.elemental_resistances.get(element, 0.0)` (`:478`) → `compute_elemental_damage(..., res)` (`:490`); 7×7 substrate matrix `get_resistance_multiplier` applied at `:501-504`. Routed when `combatant_state` populated (`spatial_engine.py:1372-1374`). The monster→player death channel is genuinely a bespoke FLAT branch: `dmg = raw_dmg * (1.0 - self.player.armor_factor)` (`spatial_engine.py:1951`), with `armor_factor` set to a per-scenario global constant overriding the kit (`:1575-1578`). Mob is built as a resolver DEFENDER (`combatant_from_monster`, `:2457-2460`) but carries `resolver_skills=[]` (`:2508`) — not an attacker. The load-bearing premise holds exactly.

2. **Undifferentiated-resist gap (§2.B) — CONFIRMED, all four sub-claims.** (a) `_derive_stats` (`gear_generation.py:935-973`) initializes `resistances={}` and has NO effect-loop branch that ever populates it — main roll path emits empty. (b) Both populating paths even-spread: `keystone_loadout_materializer.py:274-279` (`resist_total/4.0` across the four elements, comment "diagnostic only") and `gear_catalog.py:187-191` (same value for all four). (c) `element_resistance` category exists with range `(-1.0, 0.80)` (`gear_instance_generator.py:66`) but is not minted element-keyed. (d) Aggregation is non-lossy/element-key-preserving end-to-end: `gear_schema.py:252-253` → `combatant.py:575` → `combatant.py:926` → consumed at `damage_resolver.py:478`. Endgame boss carries `elemental_resistances={}` and `"skills": []` (`t4_sim_cycling.py:1016/1082`). gandalf's "solder the middle, not a rebuild" scope characterization is CORRECT — the schema/aggregation/sim are ready; only minting is missing.

3. **Flat-anchor invalidation (§5) — CONFIRMED.** The flat channel is `dmg = raw × (1 − armor_factor)` — linear in a 0–1 scalar. The resolver uses fundamentally different functional forms: physical `scaled × (1 − armor/(armor+K))` (hyperbolic armor curve, `math_model.py:131-143`) PLUS a `compute_damage_scaling(strength)` attribute term the flat channel has no analog for; elemental `scaled × (1 − resistance) × situational_multiplier`, resistance clamped 0–0.95 (`math_model.py:116-130`), PLUS the 7×7 matrix multiplier. The flat `armor_factor` scalar does not map onto `armor/(armor+K)` (different units: a 0–1 fraction vs. an armor magnitude). gandalf is RIGHT — magnitude must be re-derived from scratch; the flat anchor is not even a valid starting point in the resolver's units. KR/Matt: the held MASTER's constraint-1 flat anchor is genuinely INVALID — drop it.

4. **Salvaged guard (§6) — SOUND.** The re-founding is correct: the prior "typing collides with the homogenization guard" argument was measured on the flat global-armor-constant-fixed scenario (HP-vs-kill-speed), which cannot adjudicate kit-defense-vs-kill-speed. Dropping that argument while preserving the guard's PRINCIPLE (no mandatory defensive checkbox), re-expressed as the §6 acceptance criterion (under-resisted kit survives by playing well; matched eases; if match-capping is the only survival path the knob-set FAILS), genuinely preserves the principle. The reversal did NOT quietly lose it — the principle is re-expressed on real typed per-kit defense, which is strictly a stronger test than the flat sweep ever was.

5. **Anti-tax ruling (§3) — COHERENT and genuinely distinct from PoE/D2 tax.** The distinction is structurally real: the trial-boss gallery gives a KNOWN signature element per boss (vs. PoE's randomized content forcing blind 75/75/75 caps). "Build against a named threat" + "resistance is a continuous margin lever, never a binary safe/dead gate" + the §3.3 magnitude band (matched=comfortable, unmatched=hard-but-doable, never one-shot/faceroll) does NOT collapse back into a mandatory cap UNDER ONE CONDITION (see Concern 2). The §3.4 spirit-swap payoff (form-selection as defensive read) is the genuine differentiator that converts the genre's most-resented chore into the game's load-bearing pillar. The headline survives scrutiny. NOT a push-back.

6. **§4 confirm-trace (sizing) — RESOLVED: it is the MEDIUM-add branch, not the small preserve-through branch.** gandalf flagged this as genuinely open ("either way the schema/aggregation/sim are unchanged"). Source resolves it: neither `PartitionModifier` (`partition_schema.py:505-530`) nor `RolledPartitionModifier` (`:533-546`) carries ANY element field — identity is `modifier_id` + `category` only. The projection at `keystone_loadout_materializer.py:250-251` matches resist purely by modifier_id prefix and pools `m.magnitude` with no element read. So a rolled `element_resistance` modifier does NOT carry a target element today — element SELECTION must be ADDED to the roll (the medium branch), not merely preserved through the build. gandalf's BOUND still holds (schema/aggregation/sim genuinely unchanged downstream — the element key is preserved from `GearStats.elemental_resistances` onward), so the prerequisite cannot balloon into a downstream rebuild. But the size is the larger of the two he named — rocket should plan for element-assignment-at-roll, not a one-line preserve fix.

## Concerns the MASTER re-draft MUST carry

1. **[CARRY — INFO] Flat-anchor numeric provenance drift (cosmetic, but clean it).** gandalf's §2.A/§5 cite `PLAYER_ARMOR_FACTOR_VS_BOSS≈0.76` and `MOB_DAMAGE_SCALE=4.0`. The LIVE source constants are `PLAYER_ARMOR_FACTOR_VS_BOSS = 0.95` (`spatial_engine.py:159`) and `MOB_DAMAGE_SCALE = 0.40` (`:228`). The `0.76`/`4.0` numbers are *calibration-grid search targets* from `defensive-axis-calibration-diagnose-2026-06-21.md` (the 0.76 row at `:228`; scale=4.0 at `:219`), faithfully carried from the held MASTER (`MASTER.md:5/46/102`) into the design-half. So gandalf transcribed the MASTER correctly — the drift is MASTER↔source, pre-existing, NOT introduced here. It is MOOT for the design (§5 discards ALL flat anchors), but the re-draft should either cite live constants or explicitly label 0.76/4.0 as "superseded grid targets" so no one mistakes them for live engine state.

2. **[CARRY — design constraint, gamora+rocket joint] The anti-tax ruling (§3) holds ONLY IF the §4 generation anti-tax constraint holds.** The §3 distinction from PoE-tax is contingent on §4's "do NOT make broad all-element resist trivially stackable to where cap-everything dominates match-the-fight." If generation lets a kit cheaply reach high all-resist, the signature-boss design silently collapses back into "cap everything" — the exact tax it claims to avoid. This is a generation+calibration JOINT constraint (gandalf names it; gamora+rocket must converge the shape). The re-draft must make this constraint a first-class acceptance gate, not a footnote — it is the single point where the headline could quietly fail.

3. **[CARRY — sizing] §4 is the MEDIUM add (element-selection-at-roll), confirmed at source.** Per Claim 6 above. rocket should size against element-assignment-added, not preserve-through. The downstream bound is intact (no schema/aggregation/sim change), so this does NOT change the wave's blast radius — only rocket's prerequisite estimate.

4. **[CARRY — empirical complement, already structured] §5 spine soundness is the Stage-0a spike's job, not this gate's.** I confirmed the resolver READS off a generic defender and the mob is already built as a resolver defender, so the player-as-defender direction is structurally available. But whether `resolve_skill` routes player-defender + mob-ATTACKER cleanly (mob currently `resolver_skills=[]`; needs typed attacker skills minted) is the empirical question the gamora 0a spike must answer. My DESIGN gate PASSES; 0a is the required empirical complement before the re-draft commits, exactly as §9 structures it.
