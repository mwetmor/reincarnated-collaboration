## What I found

The committed code implements the four coordinate-derived floor rules genuinely keyed on the bc-cell 8-tuple, with no archetype label anywhere in the diff. `_reserve_floor_slots` (composer `:_reserve_floor_slots`) fires Rule D iff `def_bin == "glass"`, Rule M iff `eng_bin.endswith("-fast")`, and Rules A+B iff `geo_bin == "single-target"` — each a single-coordinate predicate, exactly as the smuggle-test (math-note §3) specified. I re-ran rocket's smoke harness independently (`python3 scripts/rocket_envelope_role_floor_smoke_2026_06_15.py`): the numbers are real, computed from emitted `s.role`/`s.geometry`, not asserted. Rogue cell (glass/fast/ST): **defensive 0→1, burst 0→1, mobility 2, area 6, geo_distinct 13, zero caster leak** at both power=50 and power=58 (the sub-60 band that was the diagnosis point). The decisive label-free proof is the C-framing (mitigator/slow/ST): **defensive=0, mobility=1** (D and M correctly do NOT fire) while burst=1 and area=6 DO fire — a re-introduced rogue label would have floored all four on the rogue-shaped cell only. The rules are genuine single-coordinate predicates.

J1 (distinct-first per sub-pool): `_draw_distinct_from_pool` draws weighted-without-replacement from `sub_pool ∩ palette` minus already-`used` geometries, appending each distinct pick to the shared `used` set — so floor slots tile distinct geometries and the free-slot draw (`_draw_geometry_distinct_first_excluding`) deconflicts against `reserved_geos`. The `geometry_only_distinct >= 10` guarantee genuinely depends on this and holds. J2 (melee AoE pool = exactly 4): verified `_AOE_PHYSICAL_GEOMETRIES ∩ PHYSICAL_GEOMETRY_PALETTE = {cone, ground_slam, melee_arc, whirlwind}` — the ranged-unlock geometries (multi_projectile/fork/ring) are excluded from the melee palette; the A floor is `min(ceil(0.25*kit_size), len(aoe_pool))`, so it never over-draws. The zero-slack melee probe returns geo_distinct=10 at kit_size=10 and 11 at kit_size=13, no over-draw, no failure, exactly as rocket reported. J3 (D-before-M): the reservation is literally sequenced D→M→A→B in `_reserve_floor_slots`; D consumes `defensive_dash` (preferred, first in `_DEFENSIVE_FLOOR_GEOMETRIES`) into `used`, leaving the M sub-pool `{dash_attack, leap_strike}` = exactly 2 distinct for 2 slots, confirmed by mobility=2 in the live run.

A1 NEVER-cross holds at code level: every skill (floor and free) is generated via `grammar.generate(role, "physical", ..., forced_geometry=geo)` (`:537-541`), and `geo` for floor slots is drawn only from physical-palette sub-pools — so the `forced_geometry` short-circuit (`ability_grammar.py:469-470`) bypasses the `defensive→self_buff/teleport` caster map. Live run: zero caster leak across all 6 DB framings + 2 melee probes. Burst reconciliation is correct: `_role_for_geometry` retains `power_tier >= 60` (`:248` equiv) ONLY as a free-path spikiness up-weight, and burst PRESENCE is floored by `geo_bin == "single-target"` independently — so the sub-60 single-target cells (power=50/58) get burst=1, which was the entire bug. Principle-6 holds: no new field (reuses `Skill.role`), no MIGRATION.md (the `def_bin`/`eng_bin` params are optional within-seam read-only coords; legacy callers omitting them simply don't fire D/M — backward-compatible, confirmed by the C-framing path). Scope is clean: 3 files (composer, smoke harness, AGENT_STATE), no b6 deletion, no class_generator live-wiring, no caster/architectural change, no label string.
