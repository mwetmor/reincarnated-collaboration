## § 2 · W1 findings

### WARN-1 · The § 4.7 instrument bound a HEAD that moved during the run, and cannot see `join2_rulebook` (#75) → fold into E2b

**What happened.** The README discloses it honestly. The run started at `85b19164` and E1-b landed mid-run, so Limb B recorded `fd219ea1`. I confirmed the two commits differ by exactly one `.md`, so **this verdict stands.** But s47 v2 records HEAD once and does not refuse a moving HEAD. Under push-as-work-lands with several seats committing, that is a live hazard: the verdict can bind a tree the run never measured.

**Second gap: `join2_rulebook` is importable by name in every interpreter on this host.** The editable install puts `/Users/admin/Games/reincarnated-engine/src` on the default `sys.path`; I checked this Gate. So an ORACLE interpreter **can** import it. The only protection today is that nothing does. Limb B's name filter (`reincarnated*`) **cannot see it**, so the README's "Nothing from `join2_rulebook` loads" is true but **not measured** by the instrument quoted for it.

**Action, inside E2b (Limb B′), not before it:**
- **(a)** Record HEAD at start **and** end, and refuse (no verdict) on a mismatch.
- **(b)** A-4(1)'s path check explicitly covers `<engine>/src/join2_rulebook/` **because** that directory is on the default `sys.path`. Add that fact to B′'s own docstring.
- **(c)** NC-J2-8 limb (b) (binder under `join2_rulebook`) is now the control that proves (b) can go RED.

### INFO

- **INFO-1 (for E3, JOIN provenance).** Because HEAD src is on the default `sys.path`, A-1's per-pid check of the rulebook worktree's **tree OID** does not prove the **loaded** copy came from that worktree. Add to the per-pid assertion: every `sys.modules` entry named `join2_rulebook*` has its `__file__` under the pinned rulebook worktree path. Refuse otherwise.
- **INFO-2 (for E2c).** The registry face has no row for the sealed **non-health routed** class:
  - `NON_HEALTH_DAMAGE_TYPES = {"SlowManaLeach"}` (threat :209), routed **before** `mitigate` at :2029;

  Today SlowManaLeach appears only as "refused". In the oracle it is routed, not refused. Add a declared `NON_HEALTH_ROUTED` row to the intake half and the face when `mitigate` is transcribed, so the face states the oracle's behaviour.
- **INFO-3.** `summon_applied`'s physical branch reads `defence[col]` and raises a plain `KeyError` if the column is absent. That is the same as the sealed code and still a `KeyError`, so the contract holds. Raising `OffenseColumnAbsent` there too would give one refusal face per lane. Optional.

It is not behavioural evidence that each stream reads that column. The behavioural proof is NC-J2-4 in-run and the A-2 rows 7, 11 and 12 parity (E3/E4). Do not quote the source check as that proof.

R-5 of the binder refuses a signature mismatch, so A-2 row 10's installed object must be an adapter with the sealed signature. Name **that adapter**, not `summon_applied`, in the row and in the scan output.
