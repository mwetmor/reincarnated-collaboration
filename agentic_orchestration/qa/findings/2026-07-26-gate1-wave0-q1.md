## Verdict

**CONCUR-WITH-NOTES.**

Roll-then-discard is correct for the application class the ruling was actually written about
(ailments + silence). Its premise is verified in code, and it is the only ordering under which
Clauses 1 and 2 are jointly satisfiable for that class. Four notes attach; none of them overturns
the ruling, and one of them retires the pre-registered fallback's named cause.

---

## 1. Premise check — HOLDS for the ruled class; MOOT for three others

**The ailment path does consume an RNG draw per application attempt.**

`damage_resolver.py:1610` — inside `_try_apply_ailment`:

```python
if not did_apply_ailment(BASE_AILMENT_CHANCE, defender.status_resist, float(rng.random())):
    return
```

A structurally identical second draw exists for `silence` at `damage_resolver.py:1185`. Both are on
the main fight `rng`. At C2's measured frame size (13,525 corpse *attempts* per 64-cell arm), a
before-roll short-circuit would remove on the order of ten thousand draws from the main stream per
arm, shifting every downstream dodge / block / crit roll. **Clause 1 dies under before-roll. The
ruling's premise is correct and Q-1 is not moot.**

**But it is moot for at least three application classes, and the math note should say so rather
than pay a wasted-draw tax it does not owe:**

| Class | Draws consumed | Q-1 status |
|---|---|---|
| ailment (`_try_apply_ailment`), `silence` | 1 on `rng` | **live** — roll-then-discard applies |
| mark (`spatial_engine.py:3697` → `_add_or_refresh`) | 0 | moot — deterministic, both orderings byte-identical |
| buff / shield / HoT appends (`damage_resolver.py:1152/1164/1173`) | 0 | moot |
| DoT ticks (`effect_resolver.tick_effects`) | 0 in production | moot — see below |

On the tick path: `tick_effects` never touches its `rng` parameter (the body has no `rng.random()`),
and its only draw is `rng_dmgvar.uniform` at `effect_resolver.py:100`. The spatial engine calls it as
`_tick_effects(e.combatant_state, self._tick_size, self._resolver_rng)` (`spatial_engine.py:5128`) —
**no `rng_dmgvar` argument**, so DoT ticks are draw-free in production. Separately,
`spatial_engine.py:5122` already skips `not e.is_alive`, so DoT-on-corpse does not tick at all today.

## 2. Joint-satisfiability check — SATISFIABLE. The pre-registered fallback's named cause is NOT present.

**Clauses 1 and 2 are jointly satisfiable under roll-then-discard for the ailment class, and the
divergence cause gandalf pre-registered does not exist there.**

After the roll, `_try_apply_ailment` mutates only `defender.active_effects` — via `_add_or_refresh`
or `_add_poison_stack`. No attacker field is written on that path. `silence` is likewise
defender-only. So the pre-registered candidate cause — *"an application class that fed attacker-side
state from corpse hits pre-gate"* — is **absent from the soft-CC class that motivated the wave**. The
fallback will not fire for the reason it was written.

The structural reason Clause 1 is cheap to hold is worth stating plainly in the math note, because it
is the real invariant:

> In production, `resolve_skill` is reached only through
> `spatial_resolver_adapter.resolve_spatial_hit` (`:318`). The **only** value carried back to the
> spatial entity is the `total_damage` float. `defender_state.hp` is scratch, re-seeded per hit at
> `spatial_resolver_adapter.py:314` (`defender_state.hp = max(defender_live_hp, 1.0)`); attacker-side
> mutations are not carried back. **Clause 1 therefore holds iff the gate never removes a contributor
> to `total_damage`.** Ailments, silence, marks, buffs and shields contribute nothing to it.

**Where a GUARANTEED divergence would come from instead — and it is cheaply falsifiable before code.**

`resolve_skill` iterates `for effect in skill.effects` (`:829`) in declaration order. The lifesteal
comment at `:1192` still cites an ordering guarantee from a `_sample_effects()` that no longer exists
as a function — that comment is stale. If a skill carries a **second `damage` effect after a lethal
first one**, or **any damage effect after `execute`** (`:991` sets `defender.hp = 0.0` then
`continue`s), then gating the damage class removes a `total_damage` contributor → the returned float
shrinks → real entity HP diverges → **Clause 1 fails in the damage class, not the CC class.**

Whether such skills exist in the corpus is an empirical question, not a design one. **Answer it with a
corpus enumeration in the math note, before the first line of gate code (Discipline #1, #10).** If the
count is zero, Clause 1 is safe and the gate is free. If it is non-zero, that is a HALT *before*
coding — which is strictly cheaper than discovering it in the smoke run.

**One attacker-side feedback path from a corpse hit does exist**, and gamora should name it rather
than gate it: `_apply_wavec_th_reflect` (`:529-530`) writes `attacker.hp` / `attacker.damage_taken`
from a hit resolved against a scratch corpse. It fires inside the damage class, upstream of the
ailment gate point, and its attacker mutation is not carried back on the spatial path. Semantic-shift
register entry; no behavior change in Wave 0.

**Clause-3 trap (adjacent to Q-1, cheap to state now).** On the spatial path the defender is *always*
alive at `resolve_skill` entry — the caller skips dead targets at `spatial_engine.py:2519` / `:2563`.
Corpse-ness is manufactured *inside* the call, by that same call's own damage, against a scratch HP
floored at 1.0. **A gate evaluated once at call entry is a no-op**: every other clause would pass and
Clause 3 (91.8% → 0.0% exact) would fail with no obvious cause. The predicate must re-read the
mutated scratch HP at each effect application, and must be written against the resolver's
`defender.hp`, not against the spatial entity's `is_alive`.

## 3. Blind-spot check — the ruling says "the application roll," singular. The damage class has four.

If the gate is extended to the damage class, one `resolve_skill` damage effect consumes up to **four
draws across two generators**, one of them conditional:

| Draw | Site | Generator | Notes |
|---|---|---|---|
| per-hit variance | `:945` `rng_dmgvar.uniform(...)` | **`rng_dmgvar`** | separate stream |
| dodge (`did_hit`) | `:1029` | `rng` | physical branch only |
| block | `:1039` / `:1083` | `rng` | both branches |
| crit (`_apply_crit`) | `:1285` | `rng` | **conditional** — only when not blocked |

"Roll-then-discard" for the damage class must therefore mean *after all four, including the
conditional crit draw and the second generator*, or byte-identity dies on `rng_dmgvar` alone. **State
the discard point per class, per generator, in the math note.**

**Second blind spot — a pre-existing PRE-roll short-circuit with the opposite convention.**
`damage_resolver.py:1607` drops a stun before `did_apply_ailment` is reached, with an inline comment
asserting byte-neutrality on the grounds that other ailments skip the branch. That is a hard-law drop
and it is not wrong — but it means the codebase carries **two opposite ordering conventions** after
Wave 0. Name it in the semantic-shift register and state why the liveness gate does not follow that
precedent (Discipline #12).

## Rationale

Discipline #1 — the ordering claim, the draw enumeration, and the multi-damage-effect corpus count
are all math-note content, and the third is the one that decides whether Clause 1 is reachable at
all. Discipline #10 — the divergence risk is empirical and falsifiable by a grep; it should not be
carried into a smoke run as an assumption. Discipline #11 — the scratch-HP contract between
`spatial_resolver_adapter` and `damage_resolver` is a two-seam interaction and is the reason both the
Clause-1 safety argument and the Clause-3 no-op trap exist. REVIEW_PROCESS #4 — the gandalf ruling
stands as authored; these are additions inside it, not amendments to it.
