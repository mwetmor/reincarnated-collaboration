## 3. Execution patterns — two options for knight-rider

### Option A: Batched knight-rider sub-agent dispatch (faster, single coordinated pass)

Knight-rider authors a single dispatch instructing each of the 8 agents (via sub-agent invocation) to amend their own OP + SKILL with the directive blocks from § 1 above. Each sub-agent makes the amendment, commits, and reports back. Total effort: ~30-45 min knight-rider authoring + ~10-15 min per sub-agent in parallel (effective wall time ~30-45 min).

**Advantages:** parallel execution; consistent verbatim text; single coordinated pass; closes the team-wide propagation gap rapidly.

**Disadvantages:** sub-agent invocation overhead; coordination of 8 parallel commits.

### Option B: Each agent amends own OP at next invocation (organic, slower)

Knight-rider files the propagation requirement in each agent's intake queue. Each agent applies the amendments at next invocation per the dispatch they're picking up. Total effort: distributed across natural session boundaries.

**Advantages:** zero coordination overhead; respects agent-ownership-of-OP convention strictly.

**Disadvantages:** propagation completion is non-deterministic; some agents may not be invoked before P1 hive-mind fires; gap persists.

**Gandalf lean:** **Option A.** P1 hive-mind preparation is the load-bearing scope; deterministic completion of propagation gates P1 sub-agent fan-out quality. Option B leaves the gap exposed for unknown duration. Option A's ~30-45 min cost is low relative to the gap-coverage value.
