```markdown
**Discipline #44 — Framing-refusal authority for sub-agents.**

Sub-agents may file a Framing-Refusal when framing-audit (Discipline #42)
returns Q3 = YES. Framing-Refusal is a formal output the sub-agent files
INSTEAD of executing the dispatch.

**Process:**
1. Sub-agent receives dispatch
2. Sub-agent runs framing-audit (Discipline #42)
3. If Q3 = YES, sub-agent authors Framing-Refusal at
   `agentic_orchestration/<agent>/refusals/<YYYY-MM-DD>-<dispatch-name>-framing-refusal.md`
4. Sub-agent commits refusal; does NOT execute dispatch
5. KR receives notification; either revises dispatch + re-dispatches OR
   escalates to Matt
6. Matt ratifies refusal + revised framing OR overrides refusal + dispatches

**Refusal templates** (sub-agents adapt as needed):
- "Dispatch presupposes Y; canonical doc Z + Discipline #N implies NOT-Y;
  please ratify Y or revise framing."
- "Dispatch acceptance criteria conflict with quality criterion W; please
  clarify which dominates."
- "Dispatch presupposes pre-authored taxonomy; Discipline #41 suggests
  substrate-emergence; please ratify the taxonomy-vs-emergence axis."
- "Dispatch implies scaffold value (Discipline #40) without flagging it;
  please amend dispatch."

**Refusal IS NOT failure.** Framing-Refusals are positive operational signal —
catching framing-flaws before execution bakes them into engine code. Tracked
in cycle close reports as quality-discipline operating correctly, not as
failure events.

**Composes with:** Discipline #11 (empirical inspection) + Discipline #13
(implicit-pillar drift) + Discipline #18 (math-before-code) + Discipline #40
(scaffold-with-pending-decision) + Discipline #41 (pre-authored taxonomy) +
Discipline #42 (framing-audit) + Discipline #43 (design-quality audit at
wave-close).
```
