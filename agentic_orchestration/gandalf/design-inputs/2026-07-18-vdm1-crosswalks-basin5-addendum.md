## §B5-ELEMENT — the no-family correction + the source-mechanism callout

### ⚠ CORRECTION — THE PHYSICAL RULE is the ONLY no-family silence (do NOT over-silence)

The crawl-audit shorthand called "physical / vitality / holy / shadow / pierce / magic" collectively "no-engine-family → element-silent." **That CONFLATES two different laws and is WRONG as a mapping instruction.** Precisely, per main-law §1:

- **TRULY no-family (element-silent) = PHYSICAL and its sub-registers only** (physical / pierce / "weapon" physical). THE PHYSICAL RULE: physical is ailment-SUBSTRATE only (carries bleed/stun/poison-venom); element-slot = the kit's *secondary* element if any, else element-neutral. Identity via geometry + ailment.
- **holy, shadow, vitality, arcane, dark, bone, necrotic, chaos, aether ALL HAVE engine families** and MAP when genuinely damage-typed: holy/sacred/light → **holy**; shadow/dark/bone/necrotic/chaos → **shadow**; **vitality → shadow** (life-drain register, §1 line 28); arcane → **shadow** (default; per-kit override legal); aether → **lightning OR shadow** (per-kit). **Do NOT silence these as "no-family."**
- **The basin-5 D2-lineage silences were NAME-ONLY (§0.2), not no-family:** chr-turret-drone "Holy Lance" (skill-name) → null; tq-squall lightning (probe-inference) → null. They stay silent because the element word was in a *name*, not because holy/lightning lack a family. **When the store genuinely types the damage — e.g. tq-distortion "physical and vitality damage in a circle" — vitality → shadow EMITS** (do not under-emit; recover the real signal).
- **Ambiguous buckets:** generic "**magic** damage" (no specific element) → element-neutral (like §1 tri-"elemental" with no dominant); "**radiant**/light" → **holy** IF damage-typed (else class-name flavor → null); "**erosion**" (no clear §1 row) → **FILE TO STEWARD** (likely poison/shadow-register by theme, but do not assert).

### SOURCE-MECHANISM-NOT-TOKEN-WORD (salience callout — basin-4 drizzle strike + LA review-book ruling)

You attest the **SOURCE mechanism** in the fetched line; **the crosswalk supplies the engine token.** Do NOT require the literal engine-token word to appear in-store. The basin-4 drizzle strike was a triple UNDER-emission because the mapper demanded the token word ("chill") rather than recognizing the source mechanism the crosswalk translates:

- **"-X% Movement Speed to enemies"** (any movement-slow / cripple / trap-slow language) → **`chill`** (main-law §2 line 41). The store need not say "chill."
- **"-X% Attack Power / -X% damage dealt by enemies"** (enemy attack/damage reduction) → **`curse:weaken`**. The store need not say "weaken."
- **"+X% damage taken by [enemy]" / "receives +X% damage" / "Brand" / named "debuff"** → **`curse:amplify`** (NOT sap — sap is defense/armor/resist SHRED only, §LA DEBUFF-DIRECTION LAW carried).
- **"-X% defense / armor / resistance"** (enemy) → **`curse:sap`** (persistent) OR **`sunder`** (timed on-hit).
- **DEBUFF-DIRECTION test still binds** (WHO takes more damage): ally/party/self damage buff → `self_buff` NO ailment (solo projection); enemy takes more → `curse:amplify`. §0-UNIVERSAL binds: the effect must be NAMED + enemy-directed in the fetched line; theme never implies it.
