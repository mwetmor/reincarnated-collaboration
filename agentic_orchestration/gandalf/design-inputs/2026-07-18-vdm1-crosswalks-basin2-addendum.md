3. **Probe facts are NEVER attestation:** `canon_probe_facts` is kb-derived pre-verification data. Mapping ailments/mechanics cite `kit_dossier` fetched language only.
4. **Skill-name collision (m03-audit ruling, BINDING RUN-WIDE):** a source SKILL/ITEM NAME is never status attestation, and supplementing a named skill's mechanics from memory is a leak class. GD/LE exposure surfaces: GD has skills/devotions whose names echo status words (e.g. anything named "Maul", "Devastation", "Stun Jacks" — the KIT gd-stun-jacks maps what fetched text attests, not what its name implies); LE ailment names overlap engine registry vocabulary heavily (LE "shock"/"chill"/"bleed" etc. are REAL LE statuses — but each still requires fetched behavioral language before an engine token routes, because LE-status semantics ≠ engine-registry semantics by default; the engine `shock`-requires-CC rule carries).
