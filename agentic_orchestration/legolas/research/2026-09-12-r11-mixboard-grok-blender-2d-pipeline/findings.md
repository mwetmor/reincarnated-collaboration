## EXECUTIVE SUMMARY

**"Grok (Animation)" is Grok Imagine image-to-video.** It is not a sprite generator and produces no sprite sheet. The creator feeds the Mixboard character sheet (9:16, solid green background) in as the **first frame**, prompts a **6-second clip**, and gets back an **MP4 — 720p, 24 fps, ~145 frames** [VERIFIED: xAI docs; fal.ai spec states "6 seconds at 720p (1280×720, 145 frames)", and 24×6+1=145]. Blender is used **only** as chroma-key + frame export.

**The green screen is not prompted into the video model.** It is in the *source still* (Mixboard prompt: *"Background: Solid green background"*), and the Grok prompt merely forbids the model from changing it. **The plate survives generation.** That is the one genuinely load-bearing mechanism in the whole workflow, and it is the same mechanism our `#00ff00` plate already relies on — the companion tutorial by the same author names our exact value: *"solid chroma key green background only (#00FF00 style green screen)"* [VERIFIED].

**So yes — this is the video-split path we already considered,** executed end-to-end by a hobbyist, published as prompts only. There are **no frame counts, no fps, no sheet dimensions, no Blender settings, and no verification step anywhere in it.** Identity is held by *exhortation* — *"⚠️ CRITICAL CHARACTER LOCK RULES… HARD RULE: if any part of the main character is cropped, the output is invalid"* — addressed to a model that has no invalidity check.

**Two things die this month and both matter:** **Mixboard shuts down 2026-09-28** (16 days; data deleted, shared boards dead) [VERIFIED, Google Labs Help]. **OpenAI's Videos API and all `sora-2*` models are removed 2026-09-24** (12 days), with **no announced successor** [VERIFIED, OpenAI Help Center]. Neither is a foundation.

**RECOMMENDATION — one line:** **Probe it, narrowly.** Not the tutorial's workflow, but its one real instrument: run Grok Imagine i2v from our existing `#00ff00` plate still, use **first/last-frame pinning on `grok-imagine-video-1.5`** for loop closure, and select frames with R10's Muybridge phase table rather than hoping. One probe, ~$1, killed fast if the model inserts a cut or the matte edge boils. **The hypothesis under test is narrow: a video model carries identity across frames by construction, which is exactly where per-frame `image_gen` fails us.** It supplies identity and inbetweening; it does **not** supply planned poses, and nothing in this tutorial pretends otherwise.

## 1. What each stage actually does

### Grok (Animation) — Grok Imagine image-to-video [VERIFIED, docs.x.ai]

| Property | Value |
|---|---|
| Model IDs | `grok-imagine-video-1.5` (current), `grok-imagine-video` (classic) |
| Modes | text-to-video, **image-to-video**, reference-to-video, **first/last frame**, video edit, video extension |
| Duration | **1–15 s** (video edit capped at 8.7 s) |
| Resolution | 480p (default), 720p; **1080p on 1.5 for t2v + i2v only** |
| Aspect | 1:1, 16:9, 9:16, 4:3, 3:4, 2:3, 3:2 |
| fps | **24** [SECONDARY — not stated in xAI docs; derived from fal.ai's 145-frame/6 s example] |
| Audio | generated by default; `generate_audio=false` to silence |
| Output | **MP4 video.** Not a sheet. Splitting to frames is the caller's job |
| Latency | async, "up to several minutes"; ~25 s for 6 s/720p reported [SECONDARY] |
| Price | ~$0.05/s (480p), ~$0.07/s (720p) + ~$0.002 image input → **6 s @720p ≈ $0.42** [SECONDARY, fal + Runware, consistent] |

**⚠ CONFLICT — reported, not averaged.** xAI's own docs describe a **`last_frame`** parameter ("pin the exact last frame"; combine with `image` to pin the first and interpolate between them; **1.5 only**), and xAI's own Grok Imagine account announces *"Choose your first and last frames, or create seamless loops."* [VERIFIED, first-party ×2]. **Runware, a third-party aggregator, states flatly: "This model only supports the first frame."** [VERIFIED as Runware's own text]. Primary source wins on capability; the aggregator is likely lagging or its integration is partial. **This is the single most load-bearing parameter for our use case — verify it against `console.x.ai` before designing on it.** Seed support is likewise unsettled: Runware returns a `seed` field, xAI's page surfaced none.

**⚠ BILLING SEAM.** SuperGrok (grok.com) and the xAI API (console.x.ai) are **separate access and billing surfaces; a consumer subscription does not include API credits** [SECONDARY, consistent across pricing write-ups + xAI docs FAQ]. Matt's Grok subscription therefore does **not** make CLI-called Grok Imagine video free. It is a new (small) spend line.

### Blender — chroma key + export, nothing else

The **Keying node** is Blender's *"one-stop-shop for green screen / blue screen removal"* and performs **both chroma keying and despill** in one node; its `Image` output carries the matte in the alpha channel [SECONDARY — quotation of the Blender manual surfaced via search; `docs.blender.org` returned a Cloudflare interstitial to automated fetch]. The workflow is: movie in → Keying node → render as **PNG RGBA image sequence**.

**The creator publishes zero Blender specifics** — no node graph, no despill value, no clip black/white, no output settings, no sheet packing. The Blender stage in this tutorial is a name, not a method.

### Mixboard — Google Labs, and dead in 16 days [VERIFIED]

Experimental AI concepting board from Google Labs; public beta launched **2025-09-23**, US-only, powered by **Nano Banana** (Gemini image editing); free in beta; exports board as PNG in a `.zip` or images individually. **Shutting down 2026-09-28** — site offline, boards and generated images permanently deleted, shared URLs dead.

Rights: Google's consumer terms assign output ownership to the user; **SynthID** invisible watermarking is present across Google's generative consumer products and is an **authenticity marker, not a rights mechanism** [SECONDARY]. There is no IP indemnity.

**Verdict: irrelevant to us.** It is a moodboard front-end over a model we can already reach directly, and it does not survive the month.

## 3. The prompts (verbatim excerpts, VERIFIED — irisogli.com)

**To Mixboard, character sheet:** *"Create a professional character design sheet… divided into three vertical sections using composition and spacing only. No borders, no frames… Top section – Reference only: Full-body front view, Full-body side view, Full-body back view, Face close-up (front view). This top reference section is used for visual guidance only and must disappear immediately at the start of the video (less than one second). Middle section: Completely empty space. Bottom section – Final character: the same character in one ideal full-body pose… Consistency rules: The character must remain 100% identical across all sections… Background: Solid green background… Aspect ratio 9:16, High resolution."*

**To Grok, animation:** *"PROMPT — 6-Second 2D Game Animation (Strict Character Lock). Create a 6-second animated video that simulates a 2D side-scroller video game scene… The main playable character must remain 100% identical to the reference design… Any characters shown in the upper part of the image are for reference purposes only. They must completely disappear at the very beginning of the video (frame 0)… ANIMATION ACTION (6 SECONDS): Create a seamless looping 2D animation: Idle → Walk → Run → Walk → Idle → perfectly back to start… Fixed 2D side view camera. No rotation, no zoom, no perspective change. Character scale and size remain identical in all frames… HARD RULE: If any part of the main character is cropped or cut off, the output is invalid."*

**Companion tutorial (same author), image-to-video via Tencent Hunyuan — note the structure:** separate clips **per state**, not one medley. *"Full body character walk cycle, fixed side profile view, walking to the right… static camera, no camera movement, locked shot… clean solid background, consistent movement"* / *"Full body character Idle stand, fixed side profile view…"*, and for the source still: *"solid chroma key green background only (#00FF00 style green screen), no environment, no shadows outside characters, no props, no text, no UI."* **This per-state variant is considerably closer to our need than the 6-second medley is.**

## 4. Assessment for our lane

### (a) Would still → clip → split → matte hold identity better than per-frame generation?

**Plausibly yes on identity. Almost certainly no on pose.** A video model conditions every frame on the first frame by construction — which is precisely the mechanism per-frame `image_gen` lacks, and precisely our unsolved problem. Vendor framing for Grok's Aurora-2 is *"subject and compositional anchoring… faithful to the source image's lighting, subject identity, and compositional framing rather than drifting toward its own interpretation"* [SECONDARY]. Circulating identity-consistency figures (~78–80% for Aurora / Wan) have **unclear benchmark provenance — do not quote them as fact.**

**But a 6 s / 24 fps clip is 145 frames of *unplanned* motion, and our dope sheet specifies 12 *planned* poses.** Nothing in this workflow lands frames on planned poses; the creator simply takes what comes. Converting a clip into a **cycle** requires stride detection, phase alignment, and 24→12 fps decimation — **which is exactly what R10's Muybridge phase table exists to do.** That is the real division of labour on offer: **the video model supplies identity and inbetweening; our oracle supplies the cut points.** That is the probe worth running, and it is *not* the tutorial's workflow.

### (b) Candidate models against subscriptions Matt has

- **Grok Imagine — viable, cheap, CLI-callable, but via a separate xAI API account** (see billing seam above). ~$0.42 per 6 s/720p clip. Has **first/last-frame pinning** (pending verification) — the only loop-closure instrument found in this survey.
- **Sora 2 / OpenAI Videos API — DEAD.** App discontinued 2026-04-26; API and all `sora-2*` snapshots removed **2026-09-24**; **no successor announced** [VERIFIED, OpenAI Help Center]. Do not plan on it.
- **Named alternatives:** Google Veo 3 / Gemini Omni, Kling, Hailuo [SECONDARY]. **HunyuanVideo-I2V (Tencent)** is the only open-weights option: Tencent Hunyuan Community License, commercial use permitted in most jurisdictions with geographic carve-outs and notice obligations on distribution [SECONDARY]. It is also the one we could run locally and audit.

### (c) Licence / ToS position for a commercial game

- **xAI:** *"you retain your ownership rights to the User Content"* (inputs and outputs); commercial use permitted on all tiers. **But** xAI takes an irrevocable, perpetual, sublicensable, royalty-free worldwide licence over User Content including for model training, and offers **no IP indemnification on any plan** [SECONDARY, consistent across readings of x.ai/legal/terms-of-service].
- **Google:** output ownership to the user; SynthID is authenticity, not rights. Moot for Mixboard specifically.
- **Tencent Hunyuan:** Community License; commercial use in most regions; notice/disclosure duties; geographic restrictions.
- **Unchanged by any of the above:** our standing rule that **no third-party pixel enters the repo.** These terms govern *our* generated output, a different question from the creator's assets — whose site ToS expressly forbids commercial reuse.

### (d) Known failure modes for cycles — the list to gate a probe against

1. **Internal scene cuts.** Grok 1.5 "sometimes generates internal scene cuts rather than a single continuous shot" [SECONDARY]. **Fatal for a cycle** — one cut and the sequence is unusable.
2. **Fast action / complex physical interaction remain weak points in 1.5, as in 1.0** [SECONDARY]. A run cycle is exactly this.
3. **Identity drift between separate generations** [SECONDARY] — so a walk clip and an idle clip generated separately may not match each other, even if each is internally consistent. This is the per-state variant's specific risk.
4. **Temporal shimmer / "boil"**: high-frequency detail boils; brightness and colour pulse frame to frame; edges "wobble slightly, as if the frame is not locked" [SECONDARY]. **This attacks the matte directly** — an unstable edge keys to a jittering silhouette, and the jitter is baked into every exported PNG.
5. **Background bleed / 1-px anti-aliased halo** from the matte cutout against tiled backgrounds [SECONDARY].
6. **Foot slide.** The clip's implied ground speed is not our engine's. Any extracted walk needs stride length measured and matched, or it marches in place / moonwalks [SECONDARY].
7. **Palette drift across re-rolls** [SECONDARY].
8. **Non-looping ends** unless first/last-frame pinning is used — prompting "perfectly back to start" is a wish, not a constraint.

## 5. Transfers now vs marketing

**TRANSFERS — three, and only three:**

1. **Plate-carry.** A green background in the *source still* survives image-to-video if the prompt forbids background change. We already mint on `#00ff00`; this extends our existing plate one stage into video at **zero new cost and zero new prompt engineering.** The companion tutorial names our exact value.
2. **In-band reference band.** Put multi-view reference in a top band of the source still and instruct the model to drop it at frame 0. Identity conditioning without a reference-image API. Testable in one call.
3. **First/last-frame pinning as a loop-closure instrument** (`grok-imagine-video-1.5`). **This is a real mechanism our `image_gen` lane does not have** — pin frame 0 = frame N, let the model interpolate a closed loop. Verify the parameter before designing on it.

**MARKETING — do not adopt:**

- **"A complete game-ready asset set… all without drawing manually."** The page publishes prompts and **zero measurements**. No frame counts, no fps, no dimensions, no verification step, no Blender settings. The quality claim is unevidenced on the page itself.
- **The prompt register.** *"⚠️ CRITICAL CHARACTER LOCK"*, *"HARD RULE… the output is invalid"*, forty lines of negative rules. **Long negative-rule stacks are the signature of someone compensating for the absence of a control surface.** Do not import this into our templates. We built oracle-derived measurements precisely so we do not have to beg the model.
