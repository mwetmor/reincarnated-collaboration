## §1 — What the inherited diff did

An HQ-2 fix was already sitting uncommitted in the tree (`w3_emission_driver.py` +60/−13
plus a test). Per the dispatch I reviewed it critically rather than authoring fresh. It was
**correct and I kept its core**:

- `run_w3_emission(..., write_band_report: bool = False)` — the write at STEP 4 is gated.
- CLI `--write-band-report` (`store_true`), wired through to the kwarg.
- The report is still **built unconditionally** and still returned in the result dict; only
  the on-disk write is conditional. That is the right split — the measurement never stops
  being produced, it just stops being *published* by accident.
- Additive result key `section8a1_band_report_written: bool`, with

  content *and* `st_mtime_ns`. This is the load-bearing design choice in the test: a
  fixture-redirected version would have passed before the fix too.

Judged against the dispatch's three questions: yes it makes the write opt-in with an explicit
flag defaulting OFF for battery/test callers; yes the test discriminates; **no, it does not
"cover the battery writer path gamora pinned" — because that path does not exist.** See §2.

## §2 — The accused was innocent (correction to charter §14.36 / HQ-2)

Charter §14.36 recorded: *"the batteries write it… star-lord's search space collapses from
'unknown import/collection trigger' to the battery writer path."* **That subject is wrong,
and it is decidable from code plus the artifact's own payload.**

- `kitcal_g5_harness.py` never reaches the writer. Its only `subprocess` use is `git rev-parse`
  for hash stamping; it contains no reference to `w3_emission`, and importing it does not pull
  `reincarnated.export.w3_emission_driver` into `sys.modules`.
- The engine contains **exactly one** writer of that path: `run_w3_emission()` STEP 4. It sits
  inside the function, not at module scope — which also retires the queue's original
  collection-time-side-effect theory (`tests/conftest.py` is 10 lines, no emission fixture).
- The only in-repo caller besides the driver's own `main()` is `tests/test_w3_emission_driver.py`,
  which calls it **12 times** (`grep -c "run_w3_emission($"` = 12), all at seed 55,000,000.
- **The artifact self-identified its writer.** The dirty live-reproduction carried
  `pilot_context.generation_seed: 55000000, n_candidates: 5` — the suite's seed and shape, not a
  battery's `74_000_8xx`.

So "the batteries mutate it" was a **true observation with the wrong subject**: the batteries and
the test suite travel together in the same lap. gamora's retraction of her own earlier
"doesn't mutate" claim was right about the *fact* and wrong about the *cause*.

This does not weaken the fix — it strengthens its placement. The gate is at the **write site**,
so it closes every caller class, including any future battery that does grow a path here.

## §3 — What I changed on top of the inherited diff

1. **`encounters` writer/validator drift — repaired (separate defect, found in passing).**
   The 2026-07-22 W3 wave made `encounters` a REQUIRED top-level key in `validate_bundle()`
   and added it to `assemble_one_realm_bundle()`. `w3_emission_driver.py` builds its **own
   parallel bundle dict** and was never updated, so every full `run_w3_emission()` had been
   halting at its own Discipline-#8 boundary for 7 days:
   `Missing required top-level key: 'encounters'`. Repaired with a block byte-identical to the
   assembler's. **No schema change** — this makes the writer conform to the shape the
   2026-07-22 entry already published. This blocked the acceptance proof: 12 of the file's
   tests could not go green until it was fixed.

   Note the ordering that kept it invisible: the §8-A1 write fired at STEP 4, **before** the
   validation halt — so even a run that ended in HALT-LOUD had already rewritten the
   measurement of record on its way to failing.

2. **Default-OFF's own failure mode, closed.** Gating the write trades a silent *overwrite* for
   a silent *non-write*: a full ADR-006-authorized run (~1500 s gauntlet + LLM spend) that
   simply forgot the flag would quietly fail to refresh the measurement of record. A non-smoke
   run that did not opt in now logs the skip at **WARNING**; smoke/battery runs stay at INFO,
   because for them not writing is the correct outcome and a WARNING there would only train
   people to ignore it.

3. **Stale comment corrected** ("Written HERE" → "Built HERE") — this file has burned people
   with a stale docstring before.

4. **AGENT_STATE precision fixes** (a concurrent star-lord thread in the same worktree had
   authored an entry; edits converged byte-identically and I reconciled to one landing):
   corrected "thirteen times" → twelve (counted), and rewrote the non-vacuity claim per §4.

5. **MIGRATION.md entry** filed — operator-facing, not drax-facing.
