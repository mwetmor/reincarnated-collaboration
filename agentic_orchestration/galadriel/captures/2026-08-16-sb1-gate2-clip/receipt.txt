8. THE FADE ARITHMETIC — v1's FINDING, RE-PROVEN AT THIS SEAT
--------------------------------------------------------------------------------
v1 banked two findings about the dip. Neither was taken on trust; both were
re-derived here before the deliverable passes ran.

FINDING A — THE LEADING ZERO IS LOAD-BEARING. `bc` prints a value below 1 with
NO leading digit, and ffmpeg refuses that outright ("Unable to parse 'd' option
value '.1666' as duration"). run_kc2_cpb_clip.sh never met this because it
passes the LITERAL $FADE for d and only COMPUTES st (which is > 1 and so always
carries its digit). The moment d is computed, it must be re-formatted. Replayed
at this seat with the deliverable's operands (N=320, FPS=30, FADE=0.50):

    DUR      = bc "scale=4; 320/30"                     -> [10.6666]
    FADE_D   = bc "scale=4; if (DUR<FADE) DUR else FADE" -> [.50]     <- no digit
    FADE_D   = ... | awk '{printf "%.4f", $1}'           -> [0.5000]  <- the fix
    ST_OUT   = bc "d = DUR - FADE_D; if (d<0) 0 else d"  -> [10.1666]

CONFIRMED: the raw bc output really is `.50`, and the runner's awk printf really
is what makes it acceptable to ffmpeg. v1's fix is SOUND and is adopted.

FINDING B — THE CLAMP IS ARITHMETICALLY INERT AT DELIVERABLE LENGTH. A 320-frame
segment is 10.6666 s, so min(0.50, 10.6666) = 0.50 and st = 10.1666. The clamp's
if-branch is unreachable at 320 frames; it can only fire on a segment SHORTER
than the fade, which is reachable only under FRAMECAP. CONFIRMED by replay.

THE FILTERS ACTUALLY APPLIED, AND THEIR DELTA FROM THE SOURCE RUNNER, DECLARED:
    this cell   A: -vf fade=t=out:st=10.1666:d=0.5000
                B: -vf fade=t=in:st=0:d=0.5000
    source      A: -vf fade=t=out:st=10.1666:d=0.50
                B: -vf fade=t=in:st=0:d=0.50
  `st` is CHARACTER-IDENTICAL. `d` is NUMERICALLY IDENTICAL and character-
  DIFFERENT — 0.5000 vs 0.50 — because this runner formats a computed d where
  the source passes a literal. 0.5000 == 0.50 as a duration; the dip is the same
  dip. Recorded because "character for character" was the charter's phrase and
  it is true of st but not of d, and a receipt that rounded that off would be
  lying by a decimal place.
