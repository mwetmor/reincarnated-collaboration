## 1. What VDM-1 was

A single autonomous **verify + dossier + map** run over the external ARPG-kit catalogue: **574 kits · 21 games · 5 basins**, each crawled → live-cited → dossiered → verify-adjudicated → mapped onto the engine's mechanic substrate, then QA'd by a blind re-projection rider (stage5) and surfaced to Matt as a single decision book (`REVIEW-BOOK.md`). One run, one human touchpoint. The eleven rulings D-1…D-11 are all Matt-ratified; the post-review migration applied them and stamped the corpus **`v1.1-verified`**.

Headline shape (ratified, invariant): 574/574 kits verified + mapped; 574/574 carry ≥1 admissible live citation (the final orphan, `ud-snowstorm-frost`, closed by a 2026-07-19 micro-fetch). For any **exact** per-kit truth — grade, elements, ailments, deviations, citations — read the live representation named in § 3, never the numbers in this prose.

**R-6 frame (load-bearing, so nobody mis-reads this archive):** MAPPED = **data**. Mapping a real-world kit onto the substrate, and ratifying a mint or docket, commits **no** engine/simulation code. A mint is a **recorded claim** ("the genre wants primitive X, evidenced by kits Y"); building happens later through the normal seams and gates when a builder pulls from the docket. This archive is a **record**, not a build authorization.

## 2. The D-11f authority inversion

**During the run, files governed.** The stage artifacts were the working truth; they flowed *into* `corpus.db` (files → DB). Corrections happened by re-crawl, re-map, re-ingest.

**At the v1.1 stamp, authority inverts.** From this point:

- **`corpus.db` (normalized) + the regenerated compendium GOVERN.** They are the single source of truth for every kit.
- **Every `stage*/` artifact FREEZES as immutable lineage.** They are read-only historical record of *how the truth was reached*. They are never edited again. Their supersession is recorded in **git**, not by in-place mutation.

The felt problem D-11 solved was **vertical fragmentation** (a kit's truth used to span `canon_corpus` ⊕ `kit_dossier` ⊕ `verify_ledger` ⊕ `kit_citations` ⊕ `kit_mapping`), not horizontal duplication (there is none — `kit_id` is PK, one row per kit). The fix: **one truth STORE + one assembled REPRESENTATION + demotions of dead parallel structure.** This README is the demotion's charter.

## 5. How corrections flow after the inversion

1. **A fact is wrong** → append an `ERRATA-N` row to `errata-ledger.md` (elrond, single writer) with a source anchor; set `errata_applied` on the touched DB row.
2. **A structural change is needed** (new column, new mint, new docket disposition) → a *new* migration doc + a bump of the corpus stamp. Never an ad-hoc DB poke, never a stage-file edit.
3. **The compendium is stale** → regenerate it FROM `kit_master` and re-stamp md5. Cheap and idempotent by design; do it whenever the store changes.
4. **VDM-2** inherits this archive read-only. Its job is to *corroborate-or-drop* the Tier-C provisional mints (`mint_ledger.evidence_tier='C-provisional'`, `build_authorized=0`) against a fresh basin, and to extend coverage — not to re-litigate VDM-1's frozen inputs.

**Provenance guard:** `corpus.db` is gitignored-local (backed up via `.bak-*` + md5 sidecars). The **git-tracked, shareable paper trail** is therefore the compendium + the MIGRATION doc + the errata-ledger + this README — not the binary DB. A future session with a fresh clone reconstructs state from those, plus the latest local `corpus.db` backup.
