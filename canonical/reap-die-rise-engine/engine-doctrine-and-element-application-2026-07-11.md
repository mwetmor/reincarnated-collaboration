# PART A — THE CANON DOCTRINE (Staged Epistemic Expansion) — canonized as authored

## A.0 The claim class

**We do not certify fun. We certify conformance to a measured envelope of genre-canonical
anchors.** This is a reference-class claim — *"this candidate behaves like content millions of
players already paid to keep playing"* — and reference-class claims are falsifiable in simulation,
which fun-claims are not. The fitness metrics (KPM, AOE%, spatial σ, and the Part-D battery) are
**canon-conformance metrics, not fun metrics**. Public language follows: *"certified to behave
within genre-canonical envelopes"* — never *"certified fun."*
⟦R-10⟧ Composes with the FUN-instrument derivation ladder (`substrate-coordinates.md` §7): the sim
is a *prerequisite to be played*; "ARPG Canonical FUN" KPIs are DERIVED from pattern recognition
over the certified canon population and must retrodict it before they are trusted to search for
"ARPG Potential FUN."

## A.1 Stage 1 — Map the canon (current stage)

- The 31+ canonical anchors ⟦= the 25 K + 6 H roster⟧ (plus gated BC cells) are the empirical
  reference distribution — canon is the *training set*, not the constraint.
- **Anchors are certified first, in OUR sim**: envelopes are drawn from anchors'
  *measured-in-our-sim* behavior, never from genre lore about how they played in their home games
  (canon's numbers were validated inside other games' density, camera, and TTK — the envelope
  inherits context, so it must be re-measured in ours). ⟦Composes with the two fit-direction laws
  canonized at `gauntlet-run-beat-families-spec.md`: genre canon = the external standard; the kit
  population is the SUBJECT under measurement, never the calibration source.⟧
- All emission (identity variations, operators, packets) bands against the anchor envelope. The
  identity tranches ride this stage indefinitely ⟦R-3: cadence vocabulary⟧.

## A.2 Stage 2 — Single-axis extrapolation (the standing R&D lane)

- **Method:** hold a canonical anchor fixed; push exactly ONE axis past the envelope edge. One
  variable per probe — **attributable novelty**: every success or failure teaches which dimension
  carried it, so later emission is aimable. ⟦"One axis" is well-defined only against the total
  inventory — the full lattice at `substrate-coordinates.md` §0–§1 is the accounting instrument.⟧
- **Deliverable per axis: the response curve** — where fun-proxies degrade smoothly (gradients)
  vs. collapse (cliffs). **Cliffs become emission masks**; peaks become candidates. (Template:
  Isaksen et al. survival-analysis parameter-space mapping.)
- **Evidence ladder** (this claim class cannot be sim-certified; gate order is fixed):
  1. sim-fair (fairness bands still apply out-of-envelope)
  2. battery reading — conformant OR anomalous, both are information
  3. **human play gate** (Hale + Judge)
  4. **arcade anomaly-slice preview** (the rotating experimental mode; the membrane makes it safe)
  5. play-data promotes or kills
  6. **survivors JOIN the anchor set** — the measured canon grows; future bands include them.
- **Cadence:** one extrapolation survivor ≈ one content-cadence mechanical ingredient ⟦R-3⟧.
  Stage 2 is not a future phase; it is the R&D lane that feeds the war chest. ⟦R-10: Stage 2's
  FUN tests fire only after the KPI instrument exists — derivation ladder stages i–iv precede.⟧
- Genre-historical confidence: much of today's canon *was built by this exact move* (zero-aim
  combat, single-mechanic-to-absurd-density builds were single-axis extrapolations that
  survived). We are mechanizing how the genre already evolved.

## A.3 Stage N — Multi-axis and new-axis search (future)

- Proceeds **only over regions whose constituent axes have known response curves** from Stage 2,
  under rules learned along the way ⟦the E4 coupling laws are the first entries in that rulebook —
  `substrate-coordinates.md` §4⟧.
- Throughout all stages, the **BC-cell hypothesis program remains the licensed out-of-band
  channel** — deliberate envelope violations, human-gated, canon-expanding. Canon-tuning is
  conservative by construction; the cell program is where the conservatism is deliberately broken,
  on purpose, with instrumentation.

# PART C — ELEMENT APPLICATION & HYBRIDITY — canonized with ruled deltas

**Resolution in one line (as authored):** hybridity is a *structure* (a kind — how a second
element attaches) plus a *rate* (a magnitude — how much), and the two live at different addresses;
neither lives in BC space or the attribute tuple.

## C-0. Placement resolution ⟦R-5 both-and applied⟧

  regression. ⟦This gate overruled the session's own converged per-CellDef % — review note §1.1;
  everything agreed survives at pins/masks/dial addresses.⟧
- Coupling to the **attribute tuple** answers a question nobody asked (stat ratios don't determine
  element blend). Attribute↔element interaction is an **operator's/T4's** job ⟦R-6: the
  scaling-unification T4 is exactly this, made flesh⟧, not baseline plumbing.

  Do-Not-Regress — the field's historical mechanical/naming double-life ends).

## C-1. The element-application block & the binder law

On the **kit packet**, alongside kernels / chain / attributes:

```
element_application: {
  primary: <element>,                 // incl. physical (Message-Q)
  secondary: <element | none>,        // HARD CAP: one
  structures: [<structure> x1..2],    // may co-occur, expressing the SAME secondary
  rate_band: splash | co_equal        // realized-share semantics, §C-5
}
```

**THE BINDER LAW:** *the element block is a binder over existing machinery, never new machinery.*
Every structure attaches elements to something another layer already built (chain slots, kernel
geometry, emission slots, hit/trigger hooks). Structure **creates capability** only in those
layers; element application **binds to capability slots that already exist.** This is the rule
that prevents every future representational collision.
⟦R-8: the binder is CODE — NEW `generation/element_application_binder.py` (rocket, E3 dispatch),
~7 one-line walkers + data map, **generation-time law** (binder stamps concrete fields; sim reads
only resolved fields; gauntlet certifies the RESOLVED kit; presentation rides the same fields).
Full resolver: `mechanical-reality.md` §4.⟧

## C-6. Affinity masks (selection vs. randomness: neither — masked sampling)

Per BC cell:

```
hybrid_affinity: {
  valid_structures: [...], weights: {...},
  hard_constraints: (carrier ⇒ emission slot present; rider/proc ⇒ hit/trigger-capable;
                     cross-family law where ruled),
  pins: anchor kits may PIN a structure (the dust-devil pins carrier; variations sample)

```

Pure per-cell selection over-authors (cells go monotone across cadences); pure randomness draws
incoherent combos. **Mask-constrained sampling with pin-capable anchors** is the standing pipeline
pattern applied here. ⟦Ruled pins: K15 `chain_partition`+`co_equal`+scaling-T4 · K20/K23 splash ·
H5 → `flat_split` at v2. This pattern also dissolves the batch-2 sample-vs-pin fork — anchors PIN,
variations SAMPLE under masks (review §3).⟧

## C-7. Certification & blacklist seeds — canonized as authored

Hybrid kits run the standard gauntlet **plus** a realized-share check against the declared band.
Pre-registered degenerates: **Blend** — dual-DoT rule-packages stacked on the same output at
co-equal rate. **Carrier** — DoT-via-emission stacking; emission-recursion element stacking (the
depth-2 cap holds). **Partition** (the new class — partitions replace rather than add, so they're
fairness-benign on damage but relocate *rule-packages* onto roles) — a control/chill package
partitioned onto a high-frequency chain role = perma-slow engine; a DoT element
geometry-partitioned onto a high-tick zone class = stacking exploit. **Exploiter hunting ground:**
the chain-role × rule-package interaction matrix.
