## § 0 — Why this exists

After the substrate-coupling archaeology surfaced 13 sites of hardcoded canonical-four element labels, Matt asked a deeper question: *"Did you specifically look at archetypes btw? Are they converged/coalesced combinatorially, or are some/all hard-coded or preferred?"*

The combinatorial-vs-hardcoded question materially affects substrate-expansion scope. If archetypes are combinatorially generated from primitives, substrate expansion 4→7 propagates cleanly (4 roles × 7 substrates = 28 archetypes emerge for free). If archetype shapes are hardcoded per (role, element) pair, expansion requires authoring N new archetype templates manually — a much bigger lift and a much bigger convergence risk.

A second archaeology pass ran 2026-05-17 against `reincarnated-engine/src/reincarnated/generation/`, `canonical/`, `spirit_guide/`, and `anchor/` to surface archetype-level coupling.

This doc is the record of what was found.

## § 1 — Headline summary

- **Total archetype-keyed coupling sites found:** 10
- **HIGH-severity:** 3 (b6_archetype_templates hardcoded dict; archetype_classifier dispatch; stat_allocator fallback)
- **MEDIUM-severity:** 6 (action register; element biases; geometry biases; constraint checkers; b6_kit_builder; monster archetypes)

## § 2 — HIGH-severity sites

### Coupling #1 — ArchetypeTemplate hardcoded dict (the load-bearing site)

**File:** `reincarnated-engine/src/reincarnated/generation/b6_archetype_templates.py:99-465`
**Pattern:** TEMPLATE-DRIVEN with HARDCODED (role × element) matrix.

A frozen dict `ARCHETYPE_TEMPLATES` with exactly **14 hardcoded templates:**
- 4 elemental mages (fire_mage, water_mage, earth_caster, wind_caster)
- 4 elemental controllers (fire_controller, water_controller, earth_controller, wind_controller)
- 1 hybrid_mage *[hybrid_mage RETIRED 2026-05-18 per canonical-6 transition; this reference is historical record. The canonical roster is now 13 archetypes. See `canonical/story/canonical-6-transition-retire-hybrid-mage-2026-05-18.md` for context.]*
- 1 hunter (physical)
- 3 other physicals (physical_warrior, physical_grappler, physical_skirmisher)
- 1 rogue (physical)

Each template specifies kit sizes, AOE coverage targets, element distribution, chain-count ranges, tier_depth, `geometry_bias` (geometry weight multipliers PREFER=2.0, PENALIZE=0.1), `required_roles`, and `special_constraints` tags.

**Combinatorial status:** TEMPLATE-DRIVEN — new (role × element) pairs cannot be generated by adding a substrate to the registry. Each new archetype requires a full ArchetypeTemplate.

**Substrate-expansion impact:** Adding lightning + holy + shadow means authoring **9 new templates** (3 substrates × 3 minimum roles: mage, controller, caster). Or, if the diversity architecture's Path (a) refactor lands, **0 new templates** because composition happens at boot from substrate identity declarations × role shape templates.

**Fix-shape:** Path (a) refactor — replace hardcoded dict with on-boot composition from `ELEMENT_PROFILES × ROLE_SHAPES`. Per substrate-expansion-decision § 5.7 (pending).

### Coupling #2 — Archetype classifier dispatch

**File:** `reincarnated-engine/src/reincarnated/generation/archetype_classifier.py:9-44`
**Pattern:** HARDCODED string-literal dispatch.

```python
def classify_archetype(dominant_element: str, ..., role_orientation: str = "damage") -> str:
    if dominant_element == "physical":
        if energy_type == "combo": return "rogue"
        if energy_type == "focus": return "hunter"
    if role_orientation == "control":
        return f"{dominant_element}_controller"  # → "lightning_controller", but no template exists
    if role_orientation == "hybrid":
        return "hybrid_mage"  # [hybrid_mage RETIRED 2026-05-18; this branch commented out in engine per rocket v1.17]
    if dominant_element in ("fire", "water"):
        return f"{dominant_element}_mage"
    if dominant_element in ("earth", "wind"):
        return f"{dominant_element}_caster"
```

**Combinatorial status:** IMPLICIT-PREFERENCE — dispatch is mechanically combinatorial, BUT allowed combinations are hardcoded as string literals.

**Substrate-expansion impact:** **Failure cascade.** New substrates produce tag names that have no template → kit builder crashes with `ValueError("No B6 template for archetype")` at lookup (b6_kit_builder.py:82-84).

**Fix-shape:** Either (a) extend dispatch to new substrates by adding string-literal branches (Path b manual authoring), or (b) eliminate dispatch entirely via Path-a refactor (archetype tag derived from substrate identity + role declaration).

### Coupling #3 — Stat allocator per-archetype templates

**File:** `reincarnated-engine/src/reincarnated/generation/stat_allocator.py:10-36`
**Pattern:** TEMPLATE-DRIVEN.

16 hardcoded archetype stat templates (14 from b6_archetype_templates + 2: `support_healer`, `tank`). Each specifies INT/VIT/DEX/WIS/STR allocation.

**Convergence risk:** New archetypes fall back to **hybrid_mage stats** (INT/WIS 100/100) — silent convergence. Lightning_mage at gen-time has the *exact same stat distribution* as a hybrid mage, not the lightning-coherent profile a Sorceress-Lightning archetype would need.

**Fix-shape:** Compose stats from substrate identity declaration's `scaling_attribute` + role shape's stat-emphasis pattern.

*[hybrid_mage RETIRED 2026-05-18 per canonical-6 transition; this Coupling #3 reference is historical record AND has a live engineering follow-up. Post-canonical-6, the stat_allocator fallback target (hybrid_mage) is a retired archetype — the fallback behavior should become a `ValueError` on unrecognized archetype rather than silently falling back to a retired archetype's stats. Rocket retained hybrid_mage stats in `_PHYSICAL_STAT_PROFILES` for Pattern P7 continuity with retirement comment, but the stat_allocator.allocate_stats() fallback path should be cleaned up in a future dispatch. See `canonical/story/canonical-6-transition-retire-hybrid-mage-2026-05-18.md` § 8.3 for context. Flagged as non-urgent follow-up.]*

## § 3 — MEDIUM-severity sites

### Coupling #4 — Archetype action / role-function registers

**File:** `reincarnated-engine/src/reincarnated/generation/class_generator.py:85-122`
**Pattern:** TEMPLATE-DRIVEN — `_ARCHETYPE_ACTION_REGISTER` (e.g., fire_mage → "arcane_channel"; physical_warrior → "martial_combat") + `_ARCHETYPE_ROLE_FUNCTION` (e.g., fire_mage → "burst"; wind_caster → "mobility").
**Convergence risk:** New archetypes fall back to `"arcane_channel"` + `"specialist"` generic defaults → archetype loses embodiment identity.
**Fix-shape:** Compose action/role-function from substrate identity declaration's `cosmological_commitment` + role shape's role-function pattern.

### Coupling #5 — Element biases (scaling + ailment + control)

**File:** `reincarnated-engine/src/reincarnated/generation/element_biases.py:8-58`
**Pattern:** IMPLICIT-PREFERENCE — `ELEMENT_SCALING_ATTRIBUTE`, `ELEMENT_AILMENT`, `AILMENT_IS_CONTROL` dicts bind mechanical signatures to element names.
**Convergence risk:** Missing entries → crash or fall back to physical defaults. Electric/holy/shadow lose mechanical signature.
**Fix-shape:** Substrate identity declarations carry `scaling_attribute` + `ailment_signature` fields; element_biases reads from substrate identity registry.

### Coupling #6 — Per-archetype geometry bias (silent neutralization)

**File:** `reincarnated-engine/src/reincarnated/generation/b6_archetype_templates.py:469-507`
**Pattern:** BIAS-LAYER — each archetype template carries `geometry_bias` dict (PREFER 2.0× / PENALIZE 0.1× / NEUTRAL 1.0×).
**Convergence risk:** **The silent-neutralization convergence vector.** New substrates without explicit `geometry_bias` get neutral 1.0× weights across all geometries → no archetype flavor → lightning_controller and wind_controller generate identically-shaped kits.
**Fix-shape:** Geometry bias composed from substrate identity declaration's `geometry_affinities` × role shape's geometry-emphasis pattern.

### Coupling #7 — Special constraint checker registry

**File:** `reincarnated-engine/src/reincarnated/generation/b6_kit_builder.py:732-764`
**Pattern:** TEMPLATE-DRIVEN with BIAS-LAYER — `_CONSTRAINT_CHECKERS` dict maps constraint tags (e.g., `require_burn_ailment`) to validator functions. Each archetype template specifies which constraints apply via `special_constraints` list.

**Critical:** Line 480 — *"Unknown tags are silently skipped."* New archetype constraint tags (e.g., `require_shock_ailment`, `require_consecration_aoe`) without registered checker functions are **silently ignored — invalid kit shapes pass validation.** Pattern P7 silent-acceptance instance.

**Fix-shape:** Constraint checkers registry must fail-loud on unknown tags; new substrate identity declarations include constraint definitions that get auto-registered.

### Coupling #6b — b6_kit_builder element sampling

**File:** `reincarnated-engine/src/reincarnated/generation/b6_kit_builder.py:191, 201` — covered in substrate-coupling archaeology (Coupling #6). Listed here for completeness; archetype-side concern is that hybrid/tertiary selection respects archetype-element-affinity constraints.

### Coupling #8 — Monster archetype pool

**File:** `reincarnated-engine/src/reincarnated/generation/monster_generator.py:59-141`
**Pattern:** INDEPENDENT TEMPLATE-DRIVEN — monster archetypes are 6 hardcoded types (brute, caster, swarmer, sniper, controller, tank) in parallel dicts (`ARCHETYPE_ROLE_POOLS`, `_MONSTER_ROLE_ORIENTATION`, `ARCHETYPE_MOVEMENT_SPEED`).
**Convergence risk:** Decoupled from player archetypes but element-set-constrained. New substrates require parallel monster-side entries.
**Fix-shape:** Substrate-identity-declaration-driven monster generation; monster shapes compose from substrate × monster-role.

### Coupling #9 — Earth_caster B11 deferred constraint

**File:** `reincarnated-engine/src/reincarnated/generation/b6_archetype_templates.py:169-176`
**Pattern:** DEFERRED-BIAS commented-out constraint (`tier1_ground_slam_and_melee_arc`) because B11 geometry palette is too small.
**Note:** Evidence that archetypes are **shape-constrained**, not just role-constrained, and that geometry-palette expansion may be a substrate-expansion prerequisite for certain archetype shapes (lightning may have similar geometry-palette gaps).
**Fix-shape:** Surface to gandalf for geometry-palette × substrate-affinity gap analysis in substrate identity declaration work.

### Coupling #8b — Role constraints

**File:** `reincarnated-engine/src/reincarnated/generation/role_constraints.py:27-114`
**Pattern:** FULLY COMBINATORIAL within the file — element-agnostic and archetype-agnostic role primitives.

**Status at this archaeology layer:** GOOD PATTERN — role primitives are reusable across substrates.

## § 6 — Verdict and diversity-architecture impact

### § 6.1 — The engine does NOT auto-generate viable archetypes for new substrates

Manual authoring is required across 5 hardcoded layers:

1. **ArchetypeTemplate** (Coupling #1) — kit shape parameters
2. **Classifier dispatch** (Coupling #2) — string-literal cases
3. **Stat allocator** (Coupling #3) — per-archetype stat templates
4. **Action / role-function registers** (Coupling #4) — embodiment mapping
5. **Element biases** (Coupling #5) — scaling + ailment + control mapping

Plus the silent-bias layer:
6. **Geometry biases** (Coupling #6) — neutral fallback = silent convergence
7. **Constraint checkers** (Coupling #7) — silent skip = invalid shapes pass

### § 6.2 — Path (a) vs Path (b)

**Path (a) — Refactor to combinatorial composition.** Replace 14 hardcoded templates with on-boot composition from `ELEMENT_PROFILES × ROLE_SHAPES`. Substrate expansion becomes architecturally combinatorial. ~1-2 weeks rocket+gamora. **Recommended** per substrate-expansion-decision § 5.7 (pending § 5.7 amendment).

**Path (b) — Accept manual-authoring tax.** Author ~9 new ArchetypeTemplate entries + 9 classifier dispatch cases + 9 stat-allocator entries + 9 action/role-function entries + 3 element-bias entries + ~30-50 geometry-weight assignments × 3 substrates + per-substrate constraint registrations. ~3-5 days authoring + balancing + testing. **Recurring tax on every future substrate addition.**

### § 6.3 — Top 3 convergence vectors

1. **Geometry bias silent neutralization** (Coupling #6) — without explicit geometry bias, new substrates produce identically-shaped kits.
2. **Stat allocation fallback** (Coupling #3) — falls to hybrid_mage stats → silent convergence; unbalanced classes pass. *[hybrid_mage RETIRED 2026-05-18; fallback target is now a retired archetype — see Coupling #3 annotation above for engineering follow-up.]*
3. **Constraint checker silent skip** (Coupling #7) — unknown tags silently skipped → invalid kit shapes pass.

These are the three sites where the diversity architecture's Layer 1 (substrate identity declaration) + Layer 3 (mirror-match diversity gate) need explicit attention to prevent silent failures.
